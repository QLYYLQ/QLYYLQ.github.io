moteus 控制板 r4.5 升 r4.5b：工作区泄题

PCB难工作区泄题已修，待重跑

这道题取自 moteus 电机控制板的一次提交（2021-04，“Capture r4.5b as sent for eval”）：r4.5 改成 r4.5b，驱动芯片从 DRV8323RS 换成 DRV8353S，因为新芯片没有内置降压，所以要自备 3.3 V 降压，再加第二路编码器接口。文件是 Eagle 原生格式。

Sonnet 一打开工作区就发现，顶层的 controller.sch、controller.brd 里已经有 DRV8353S、MAX15062 这些改后才有的东西，拒绝作答，没有交板。核对后的原因在工作区，不在模型：上游这次提交只是把改好的顶层文件复制归档成 r4.5b/ 目录。搭题时只检查了“改前仓库里有没有 r4.5b 目录”，没有比较文件内容。

2/2个顶层文件与上游 r4.5b 逐字节相同（本页用 GitHub 原文件重算 sha256）
0Sonnet 交的板（拒答）
105 → 122个封装，r4.5 到 r4.5b（本页用 KiCad 导入重算）
47条必需检查，上游 r4.5b 全过（题包 README）

题题目

题面给的是 mjbots/moteus 的仓库快照（断网、无 git 历史），设计文件是 Eagle 的 .sch 和 .brd。要在新目录 hw/controller/r4.5b/ 里交付改好的两个文件，旧的 r4.5 不能改。

R1 换驱动
DRV8323RS 换成 DRV8353S（SPI 版，不带降压模块），栅极、电流采样、SPI、使能、故障等连接保持 r4.5 的定义，按手册配电荷泵和 DVDD、VGLS、VCP 的电容。旧降压外围（D1、R11、R12）不应留下。
R2 自备 3.3 V
新加降压稳压器（推荐 MAX15062A），输出固定 3.3 V、不低于 300 mA，输入耐压不低于 60 V；电感、电容按手册；输出并入原来的 +3V3 网络，开关节点叫 VSW。
R3 第二编码器
新增 6 脚 Pico-SPOX 贴片直角座，位号 ENC，信号 1 到 6 为 +3V3、SECONDARY_ENC_CS、GND、AS5047_SCK、AS5047_MISO、AS5047_MOSI；CS 是新网络，接 MCU 上一个原来没用的 GPIO。
R4 母线电容
V+ 与 V- 之间加至少 1 颗 100 V 的 1 µF 陶瓷电容，再加至少 10 个 1206 的未贴电容位，沿板边成排。
R5 不变
板框、安装孔、电机焊盘、电源接口、CAN 收发器、MCU、编码器和三相 MOSFET 位置不变；r4.5 的 67 条网络除 R1、R2 明确更换的外都要保留；原理图与 PCB 一致，布通，满足设计规则。
判分
题包共 50 条检查，47 条必需、3 条参考。Eagle 的 XML 文件 KiCad 的 DRC 读不了，网表比对、连通和近似 DRC 都是自写的纯标准库代码。

过程一步一步

  1. 01
    改前

    上游父提交里，顶层文件已经是 r4.5b

    下图画的是 hw/controller/ 下相关文件的 sha256 前 8 位，都是本页从 GitHub 原文件重新算的（父提交 4dedffb2 和提交 4892d559）。上游父提交里，顶层的 controller.sch（0bfceb09）、controller.brd（5f3a4a33）和 r4.5 归档里的同名文件（73c70be3、858f20c0）不是同一个东西。上游这次提交新增的 r4.5b/ 里，两个文件的哈希恰好等于父提交的顶层文件，顶层本身没有变。也就是说，这次提交的内容是“把已经改好的顶层文件复制归档成 r4.5b”，顶层从提交之前就已经是 r4.5b 的设计了。

    r4.5b 里新增的库文件也一样：r4.5b/controller.lbr 与父提交顶层的 controller.lbr 哈希相同（5dbcdcdf）。

  2. 02
    模型的解

    Sonnet 发现泄题，没写任何设计文件

    Sonnet 在交付说明里写：未交付 r4.5b。工作区顶层的 controller.sch 和 controller.brd 已经是改后的版本，含 DRV8353S（U5）、MAX15062AATA+T（U4）、ENC（PICO-SPOX-6）、SECONDARY_ENC_CS、VSW、1 µF 100 V 电容和 15 个 1206 的未贴电容位，删除了 D1、R11、R12。它没有复制或改用这些内容，只对比了顶层与 r4.5 的元件和网络清单（只读），并建议出题时把顶层的设计文件删掉再重跑。

    这份拒答没法反映模型的真实能力。它也守住了规矩：只读了工作区里的文件，没有用泄漏的内容作答。

  3. 03
    放大看

    把两版板子导进 KiCad 对比：改动的都在泄漏的文件里

    Eagle 的 .brd 可以用 kicad-cli pcb import 导入 KiCad，所以本页把上游的 r4.5 和 r4.5b 板各导了一次来画图。导入只用于看图，不是判分用的数据，Eagle 里的一些样子（比如 ENC 座的焊盘形状）导入后会有差异。

    本页重算的差异：封装数 105 个变成 122 个；D1、R11、R12 删除；U4 从 DRV8323RS 变成 MAX15062AATA+T，新增 U5（DRV8353S）、ENC 座和 1 µF 100 V 的 C39（导入后位号是 ENC0）、15 个 1206 的 DNP 电容位 C40 到 C54，另有 C38、C55 两个 0402；板框外形没变（导入后外包 46.04×53.05 mm 一样）。r4.5 的电感 SRN4018-220M 换成了 CBC3225T330KR（33 µH），旧版 R10 变成 DNP，C20 从 0.1 µF 变成 1 µF。

  4. 04
    放大看

    答案里新增的东西一眼可见

    下图是 r4.5b 的同一块板，黄色标出新增的元件：ENC 座、U5、C39，以及两排共 15 个 1206 的未贴电容位。这些都在父提交的顶层文件里，Sonnet 一打开就能看到。

  5. 05
    自动检查

    检查本身没问题，问题在题包

    题包 README 的 11-12 修订里记了核实结果和自测，下面三条是其中和这道题直接相关的。检查只读 r4.5b/ 里的两个文件和 r4.5 两个文件的哈希，基线也是从 r4.5 冻结的，所以不需要改检查，也不需要重新冻结。

    检查查什么结果说明
    改前工作区新生成的改前工作区（顶层换成 r4.5）判分按预期不过只有 C0_files 失败（没有 r4.5b），符合预期。
    上游 r4.5b上游改后的 r4.5b 判分通过47 条必需检查全过；参考检查 C2_gnd_domain 不过，因为上游把 AGND 接了 V-，和 r4.5 的习惯相反。
    样本64 个样本（58 个故障、4 个应通过、2 个信息样本）通过58 个故障样本全被拦下，4 个应通过样本通过，2 个信息样本满足预期。
    无泄漏新工作区顶层 sch、brd 的哈希与 r4.5 归档一致，且没有 DRV8353、MAX15062、SECONDARY_ENC、PICO-SPOX 字样通过只有顶层库文件和题包材料、题面里出现这些名字。顶层 controller.lbr 保留，因为题面写明“库里已有”DRV8353S 和 PICO-SPOX，库里不含 MAX15062。
  6. 06
    结论

    已改为放入 r4.5 版本，待按新工作区重跑

    修订做法：workspace.json 加了一个 overlay 目录，用 r4.5 归档里的 controller.sch、controller.brd 覆盖工作区顶层的同名文件（哈希前 8 位 73c70be3、858f20c0），题面在起点一节补了一行，说明顶层两个文件是 r4.5 的工作副本，交付仍放 r4.5b/，没有透露答案。

    另一道 9b0b0f77 是同一改动的就地修改提交，改前顶层本来就是 r4.5，没有泄题，保留为正式题。按题包 README，两题的上游答案文件逐字节相同，所以这两题只计 9b0b0f77。

看点

版本归档式的提交会把答案藏在“改前”里：提交的内容只是把已经完成的文件复制到新目录，改前状态里的另一份文件早就是答案。搭题时只看“改前有没有答案所在的目录”不够，要把改前的工作文件和上游改后文件逐个比哈希。

这道题是 Sonnet 自己发现并拒答的，所以没有造成误判。如果模型直接拿顶层文件当答案交上去，检查是会放行的：上游 r4.5b 本身就是 47 条必需检查全过。
