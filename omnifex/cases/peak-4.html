Peak 的充电电路：issue #4 指出的电源路径设计失误

PCB中到难无上游答案位号对不上

Peak 是稚晖君的一块 ESP32 小主板。issue #4 的作者指出：锂电池充电芯片的输出既给电池充电，又给整块电路供电，外部供电时没有把电池和后级电路断开，充电芯片没法正确判断电池状态，电池一般充不满。维护者回复“这里确实是一个设计失误，感谢指出”。唯一一次改 PcbDoc 的提交 5daf5a7 在 issue 之前一天，所以一直没人改。

需求和证据都很扎实，但核对原生文件时发现一个麻烦：评论里的位号（Q4、R7）和网络名（VCC_SYS）和仓库里那份 PcbDoc 对不上。这道题要做，题面得先按仓库文件的位号重写。上游没有答案，参考解要我们自己做。

14issue 下的评论数（本页用 gh 实查）

0之后的修复提交（issue 复核记录，本页未另查）
2 / 5评论提到的 U1、Q4、R7、VCC_SYS、CHG_DET 五个名字里，在仓库文件里能对上的只有 U1 和 CHG_DET（Q4、VCC_SYS 对不上，R7 只有位号相同）

题题目（草案）

还没有加工成题。下面是按 issue 和仓库文件整理的题面方向。

起点
1.Hardware/Peak/Peak.PcbDoc 的 KiCad 转换版（仓库全是 Altium，转换结果已和 Altium 导出的焊盘、网络逐一核对，全部一致）。KiCad 读到 4 个铜层，约 31.5 × 34.1 mm，64 个封装里 61 个在背面。
需求
外部 USB 供电时，系统不再靠电池和充电芯片输出的同一个节点供电，充电芯片只管充电；拔掉 USB 时电池照常给系统供电。
评论里的改法
  • U1（LP2992 稳压器）第 3 脚改接 VCC_SYS。
  • 去掉 Q4 和 R7。
  • CHG_DET 的上拉电阻从 10K 改 1K（评论者实测：10K 时只有约 1.9 V，MCU 读成低电平；改 1K 后约 2.5 V）。
上游答案
没有。

过程一步一步

  1. 01
    线索

    issue #4：充电芯片的输出同时给电池和系统供电

    issue 由一位复刻者在 2021-10-11 提出。大意是：充电时充电芯片的输出既影响电池端电压，又要分走充电电流，充电芯片对电池状态的判断被严重干扰，电池通常充不满。作者建议外部供电时切断电池和后级电路，让整个电路改由充电芯片前端的电源供电。

    评论区一共 14 条。要点有四处：

    • 维护者 peng-zhihui 回复：“这里确实是一个设计失误，感谢指出”。
    • 评论者 yuzhou3996 贴了自己改过的电源图，之后回复“U1 的 3 号脚应该接 VCC_SYS，然后 Q4 和 R7 可以去掉”，并给了改后的图。
    • 评论者 SuperWangRong 实测 CHG_DET 的 10K 上拉只能把电压拉到约 1.9 V，改成 1K 后约 2.5 V，MCU 才读成高电平，屏幕上的电池图标状态才正确。
    • 另一位复刻者报告只接 USB、不接电池时 ESP32 反复复位，维护者回复“因为充电 IC 的影响导致电压不稳定，电池是必须接的”。

    上面的引文和时间是本页用 gh issue view 读原文核对的。issue 里的三张电路图是 GitHub 上的用户图片，本页不转载，链接见出处。

  2. 02
    改前

    仓库里的板：电池、稳压器和充电芯片的输出接在同一个节点上

    下图是 HEAD 上的 PcbDoc 转成 KiCad 后的背面视图，元件都在这一面。黄色是和这次修改有关的网络（VBAT_IN 是充电芯片的输出，VBAT 是电池和稳压器的输入，CHG_DET 是充电状态），红色是相关元件的焊盘。

    整板图里这部分电路集中在板子左半边，5 脚的稳压器 U1 旁边就是充电芯片 U3 和一对 P 型、N 型 MOS 管（Q1、Q2）。

  3. 03
    放大看

    按网表整理出来的电源路径

    下面这张图是本页根据 Altium 导出的网表画的，原理图原图没有用到。仓库文件里的路径是这样的：

    • USB 的 5 V（VUSB）进充电芯片 U3（MCP73831T），U3 的输出叫 VBAT_IN。
    • VBAT_IN 经一个 P 型 MOS 管 Q1（AO3401A）接到 VBAT。Q1 的栅极由 R3（20K）上拉到 VBAT_IN，再由 N 型 MOS 管 Q2 拉低，Q2 的栅极来自 GPIO21，旁边的 R7（20K）是这个栅极的下拉。
    • 电池座 U6 的正极、稳压器 U1 的第 1 脚（VIN）和第 3 脚（ON/OFF）、电池电压分压 R2/R4 都接在 VBAT 上。U1 的输出 VCC_3V3 给系统供电。
    • CHG_DET 来自 U3 的 STAT 脚，R11（10K）把它上拉到 VCC_3V3，R10（1K）串一颗指示灯到 VUSB。

    也就是说，只要 Q1 导通，充电芯片输出、电池和系统是同一个节点，issue 描述的问题在这个文件里同样存在。

  4. 04
    核对

    评论里的位号和仓库文件对不上

    把评论的改法逐条放到网表里核对，结果是这样：

    • U1 第 3 脚：对得上。U1 是 LP2992，第 3 脚 ON/OFF 现在接 VBAT。
    • CHG_DET 上拉 10K 改 1K：对得上。仓库里的 R11 就是 10K，接在 CHG_DET 和 VCC_3V3 之间。
    • VCC_SYS：仓库网表里没有这个网络名。issue 图里 VCC_SYS 在一个 P 型 MOS 的输出侧，对应到仓库文件，名字更接近 VBAT。这是本页的推测，没有原理图原图可对。
    • Q4：对不上。仓库里的 Q4 是 AO3400A，漏极经 R14 接背光 LCD_LEDK，栅极接 GPIO12，是屏幕背光开关。issue 图里的 Q4 是充电电路里的一个 P 型 MOS。
    • R7：只能对上位号，作用对不上。仓库里的 R7 是 Q2 栅极的 20K 下拉，issue 图里的 R7 是 10K，接在另一个 MOS 管的栅极上。

    最可能的解释是 issue 里的图来自另一个版本的原理图，位号和网络名都不同，而仓库的 PcbDoc 是一份简化版：issue 图里充电芯片输出之后还有 Q3、Q4 两个 MOS 管和二极管 D5，仓库文件里没有这一级，只有一个 Q1。这点我没能用原理图原图证实，仓库的 SchDoc 本页也没有逐页读。

    对出题的影响是直接的。评论的方案不能原样当参考解，也不能让题面直接引用 Q4、R7。题面要用仓库文件里的位号重新写需求，参考解要我们自己做。

  5. 05
    上游答案

    没有

    Peak 仓库里只有一次提交改过 PcbDoc（5daf5a7，2021-10-10，说明只有“Update Peak.PcbDoc”），早于这个 issue。本页用 KiCad 读它的前后两版，元件、网络、走线、过孔、铺铜、位置都没有变化，所以它和这次修复无关，也没法作为答案。issue 至今是 open。

  6. 06
    结论

    能出一道“改电源路径”的半成品题，判分点可以先列出来

    判分思路，都从最终的 KiCad 文件重新导出后判：

    • USB 供电时，系统稳压器 U1 的输入和电池所在的节点之间要有明确的隔离（用网络连通性判，不比对具体器件）。
    • 拔掉 USB 时，电池仍能经开关给 U1 供电。
    • CHG_DET 的上拉阻值要比 10K 小（评论者实测 1K 可用，具体上限要查 MCP73831 手册里 STAT 脚的驱动能力，还没查）。
    • 不新增 DRC 错误，未连接数不增加，改动面只在电源区。
    • 质量库的通用加权项，如去耦、courtyard。

    难度是中到难（本页估计，没有试做）。改法本身不长，但要读懂电源拓扑，并且题面和原图的位号对不上这件事，会考验 agent 是否真的在看网表。因为没有上游答案，参考解和判分都需要人工做一遍并核对。

看点

有维护者确认、有具体改法的 issue 很少，Peak #4 是其中一个，但“有人给了改法”不等于“改法能直接用”。评论里的位号来自另一版原理图，仓库文件里的 Q4 其实是屏幕背光开关。加工这类题的第一步是把线索里的每个器件名放到原生文件里逐个对一遍。

这也是一个适合放进 Altium 来源的例子：转换本身已经核实无误，难点在读懂设计，而不在转换。
