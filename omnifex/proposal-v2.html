Omnifex

从 PCB 到 CAD，让 agent 把硬件做出来

我们提议让 agent 走完从 PCB 设计到 CAD 设计的整条链：查手册、选有货的料、算元件参数、画原理图和 PCB、做出和板子配得上并留够装配余量的外壳，最后导出嘉立创下单要的整套文件。项目叫 Omnifex，用拉丁词根拼成：omni 是“一切”，-fex 是“制造者”（artifex“工匠”就带这个词尾），合起来就是“什么都能造”。交付分两部分：一是开源工具包，形态学 REA（把逆向分析软件打包给 AI agent 用的开源项目），一条命令装进 Claude Code、Codex 或 Gemini CLI；二是评测这条链的 gym，拿真实的开源硬件工程出题、自动判分，也能当强化学习环境。两部分共用一套比 DRC（PCB 的设计规则检查）更严的验证器。

题源
续调研把 25 条项目记录追到了板、机械、固件和制造包这一层，发现文件齐了也常常对不上：有的坐标文件是 0 字节，有的 BOM 只有表头，同名的板、壳、固件可能来自不同版本。所以先把每个项目存成按版本连起来的资源图，再从中截题。题以改需求为主，首批用 OpenFlexure、splitflap、Corne 出容易隔离的局部题；HEMY v2 的接口板和盖板题等它的工程对齐后再加。
判分

§1 动机

REA 火在把成熟工具交给 agent，硬件缺的也是这一层

REA（Reverse Engineer Anything）里的反编译靠的是 Ghidra、IDA 这些现成的逆向软件。它做的是打包：把这些软件连同一套工作流和一条命令的安装体验，一起交给 AI agent 用。10 月 6 日它还不到 1 万 star，10 月 22 日已经是 36.3 万。硬件这边，KiCad、FreeCAD、嘉立创、立创商城都很成熟，缺的同样是把它们串起来交给 agent 的那一层。

从 REA 搬过来的四条经验

  • 新意在包装。成熟工具、工作流和安装体验打包在一起，不懂逆向的人也能用。包装的价值也会被质疑：MindStudio 实测，不装 REA 的普通 agent 反而先完成了任务。硬件工具包同样会被这样问，所以要拿数据说明下单前多拦住了多少错。
  • 让模型做它擅长的事。REA 处理的是人看着头疼、模型不头疼的符号名和偏移量。硬件里这类活遍布整条链，PCB 只是其中一段：从几百页手册里查引脚表、寄存器和复用表，画原理图，算分压电阻、滤波电容和降额，核对料号后缀和 BOM 格式，写参数化的外壳 CAD，按加工工艺留够装配间隙和公差余量。
  • 证据换信任。REA 的每个结论都附证据和局限。硬件出错要花钱、要等快递，更需要每条连接都能追到手册第几页。
  • star 不等于使用。硬件工具最后靠“照着做能点亮”攒口碑。

拿谐波赤道仪举例

谐波赤道仪是用谐波减速器驱动的望远镜赤道仪，天文摄影爱好者常用。成品 ZWO AM5N 在美国标价 2,299 美元。开源的 HEMY v2 总成本约 800 到 1,000 欧元，其中机加件不到 400 欧元，电路板发在立创开源平台上，固件用开源的 OnStepX。按这组数字，自制大约是成品价的一半。我们最早的估计是约 2 千元做出 1.2 万元的东西，也就是不到 1/5，这要靠国内零件和加工更便宜，还没核对。

省钱适合讲故事，用户更在意一次做对：打样失败一次，就要再等一周、再花一次钱。HEMY 的电路、机械和固件都开源了，上一代 v1.1 也有人照着装起来用过，难的是按自己的需求把三样改到一起，再变成能下单的文件。

模型管信息和计算，工具管几何

模型擅长信息搬运和套公式的计算：手册里用文字和表格写的引脚表、寄存器、复用表、降额参数，料号和封装后缀，嘉立创 BOM 和坐标文件的格式，还有阻容取值、降额核算、装配间隙和公差余量。算错的情况也有（表 1 的电容例子），所以电路上的计算要过验证器的 L4 核算，装配余量要过 L6 的干涉和间隙检查。信息这一层的作用有硬数据：PCBSchemaGen 去掉手册知识后，难题通过率从 47.1% 掉到 2.0%。几何是短板：让 GPT-4o 从手册的机械图读封装，IoU 只有 11.1%；OmniLayout 的结论是 LLM 做布局推理的能力很有限。所以分工上，模型负责信息、计算和决策；外壳由模型写参数化 CAD 代码，交给 build123d 这类几何内核生成实体；布线交给 Freerouting；对错交给规则检查。

§2 缺口

单个环节已经很挤，整条链还没人评

基准方法调研读了约 60 个 PCB、电路和 CAD 基准与数据集。图 1 把其中的代表工作摆到同一条链上，我们查到的没有一个从需求走到下单包。

三个缺口合起来是主贡献

G1

没有一条做到可下单的端到端任务

查到的公开基准里，没有一个把“从需求到原理图、PCB，再到可下单的制造文件”当成一个任务来评分，也没有一个自动检查制造文件本身。最接近的 IoTGen 打样了 2 块板，但不评制造文件；EDA Bench 照 35 个开源项目重建整板，按 ERC/DRC、铜连接和近似的行为测试打分，不验收 Gerber、BOM、坐标文件是否成套一致；EEBench 把布局、打板和上电留给了后续版本，V1 只到仿真。

G2

电路和外壳没人一起评

查到的公开基准里，没有一个同时给 PCB 和外壳或机构打分。PCBWorld 只查板框边距；ASSEMBENCH、MUSE、CADEngBench 只管机构、装配或可制造性。查到的里，把两边连起来的只有 Flux 9 月底上线的外壳功能，它是商业产品，没有公开评测；IMECE 2023 有一篇 PCB 外壳自动生成的论文可能相关，没读到。可实际做东西时，接口位置一改，外壳就得跟着改。

G4

验证停在 DRC

DRC 管线距、孔径、有没有连上，管不到表 1 里这些失败。只靠规则检查判分也会偏松：PCBSchemaGen 的审计显示，只用 ERC 时通过率虚高 10 到 13 个点。

G3检索没被当成能力考
真实失败多出在选具体能买的型号和封装。T1 题让 agent 自己找手册，落到料号和封装。

G6没人按爱好者难度出题
驱动板、传感器板、外壳这一段，agent 今天最可能做成，用户也最多（嘉立创 EDA 注册用户 736.88 万）。出题时按这个难度控制。
G7几乎没有实物验证

这些“没人做”的结论都来自搜索没找到，不能证明没有。端到端方向做了 58 次搜索、约 75 次网页抓取；续调研又补读了 13 个核心基准的原文、代码和数据卡，结论没变，说法收窄成：查到的公开工作里，还没有一个对同一个可追溯项目的电路、机械配合、固件和制造文件做联合自动验收。EDA Bench、IoTGen、FunCADBench 和 Flux 的外壳功能都是最近几个月才出现的，投稿前要重查。

§3 方案

两件东西，共用一套验证器

工具包和 gym 用同一套验证器：工具包用它在下单前拦错，gym 用它判分、当奖励。验证器从第 1 周起就作为工具包的一部分来写。

工具包：冲影响力

  • 形态照搬 REA：一个 MCP server、一组 skills、一个命令行，一条命令装进 Claude Code、Codex、Gemini CLI。
  • 底层不重写，直接接现成工具：KiCAD-MCP-Server（MIT，约 2.9k star；KiCad 10 用户可以换成同一作者用 Rust 重写的 Konnect）、easyeda-agent（接嘉立创 EDA 专业版）、Freerouting（自动布线）、build123d-mcp（外壳建模，边建边渲染、量尺寸、查可打印性）、jlcparts（筛选嘉立创贴片料）、easyeda2kicad（按立创商城编号把符号、封装和 3D 模型转成 KiCad 库）。
  • 自己写四样：从需求到下单包的工作流 skills；下面的验证器；证据记录，每条连接、每个参数都附手册页码和料号快照；一键导出嘉立创要的全部文件。
  • 授权：本体用 MIT 或 Apache-2.0。Konnect 和 easyeda2kicad 是 AGPL，只当独立程序调用，不改代码，不打包进仓库，让用户自己装。
  • KiCad 和嘉立创 EDA 都支持。gym 默认用 KiCad，因为它开源、能装进容器、学术圈都在用；国内用户更多在嘉立创 EDA，它和立创器件库、下单是打通的。嘉立创 EDA 的工程（HEMY、瀚文）可以在原生环境里出题，也可以转成 KiCad；转的话要核对转换前后的连通、封装、层叠和坐标，不能默认无损。
  • 机械建模默认用 build123d：agent 在 CAD 这一段写的就是 build123d 代码，工具包只在外面加 MCP 和检查。它和 CadQuery 共用 OpenCascade 内核，能读写精确的 STEP，可以直接交给嘉立创 CNC；能做什么、要补什么，见本节末尾。题源本身是 OpenSCAD 这类开放参数源的，照旧写 OpenSCAD。SolidWorks 闭源、没有官方 MCP、装不进容器，不当底座，最后导出 STEP 给 SolidWorks 用户；项目手上的 SolidWorks 2025 用来转题源和交叉核验，见第 6 节。

操作接口分主次。主线跑两种条件：纯代码和 MCP（KiCad MCP、build123d-mcp）；agent 用 MCP 动手后看渲染图目检，也算在 MCP 里。纯代码这一条，从零写电路用 atopile 或 SKiDL，改现成的 KiCad 工程用 kicad-cli 和 Python 脚本，机械用 build123d，题源是 OpenSCAD 的写 OpenSCAD。v0 的代码对 MCP 先在卡 D、卡 E 的板子部分上比（任务卡见第 5 节），build123d 对 build123d-mcp 要等外壳题进库。屏幕操作只挑一小组题做同题对照，放在六周以后，不进主排行榜，见本节末尾。

验证器：L0 到 L6

L1 到 L6 是课题调研提的设计，基准方法调研加了 L0。续调研建议把它们当检查的分类用，不当必须依次过的台阶：每道题先声明自己的必需检查。只改抽屉尺寸的题不用跑电路仿真，板子和固件联动的题也不能只看外形分。

类别查什么现成可接的现有基准里
L0文件有效固定版本的工具能打开、能导出、能读回，文件非空，实体封闭。候选交的文件打不开，这题不通过；评测环境自己起不来，单独记环境错误，不算到模型头上。kicad-cli、OpenCascade有 PCBWorld、CADGenBench 有类似门槛

CAD 走代码，屏幕操作只做对照

外壳、支架和装配余量这一段，Omnifex 默认让 agent 写 build123d 代码，由 OpenCascade 内核生成精确实体，再交给 L6 去量；题源本身是 OpenSCAD 的（卡 A、卡 E），交原格式的源码。也可以只让 agent 看截图、点 CAD 软件来出题，但这类题不进主线，原因有两个。第一，需求用不着：这里的题是给 PCB 配外壳、按改动挪开孔、留够装配间隙，代码和数值就能把需求写清、把结果量准，换成在图形界面里点，考到的设计能力并不会更多。第二，现在的分数区分度低：下表里几个屏幕操作基准的分数普遍很低，CADWorld 列的 10 个 agent 有一半不超过 1.5%。CADWorld 作者的分析是，较弱的 agent 多半还没交出有效文件就失败了，较强的 agent 才开始在结构、几何和建模过程的要求上失分。CAD-bench 里 agent 交 STEP，多数运行能把实体建出来，失分集中在功能要求上，gym 想拉开差距的正是这一层。这些数字来自不同的基准和题目，同题的证据几乎没有，所以我们自己做一组对照，见本节末尾。

CADWorld 作者对脚本建模的批评要认：代码建的模型没有 SolidWorks 那种原生特征树，工程师没法在图形界面里回到某一步改尺寸。Omnifex 认下这个代价，题面不要求原生特征树：外壳题默认交 STEP 加 build123d 源码，OpenSCAD 题源交 OpenSCAD 源码。源码可以接着改，但 agent 也可能把坐标写死，所以题面要求关键尺寸写成具名参数，判分时改一两个参数重建来确认；gNucleus 的 CAD Bench 只查参数是不是具名的驱动尺寸，没有改参重建。SolidWorks 原生格式的题源用项目手上的 SolidWorks 转成 STEP；Fusion 的 F3Z 要在 Fusion 里打开再导出。

build123d 能做的

  • 精确的边界表示（B-rep）实体：草图、拉伸、旋转、放样、抽壳、圆角、布尔运算，按几何条件选边和面。
  • 读写 STEP（带颜色和名字），也能导出 STL、3MF、DXF、SVG、glTF。导入 STEP 后能在实体上用布尔运算开孔、补料、加凸台，正好对上第 4 节外壳题的做法。
  • Apache-2.0，0.13.0（2026-09-21），Python 3.11 到 3.14。紧固件和螺纹有 bd_warehouse，齿轮有 py_gearworks。
  • build123d-mcp（0.3.91，10-15）让 agent 边建边看：在会话里跑代码、渲染、量体积和包围盒、找孔、查可打印性、导入 STEP 比对。作者自报，同一个模型在 CADGenBench 上用了它，分数从 0.360 涨到 0.457，有效模型的比例从 88% 涨到 100%。

要我们自己补的

  • 没有全局约束求解，模型是按顺序构造出来的。装配用的 joint 只负责一次性摆位置，既不求解，也不查干涉，所以干涉、间隙和沿装配方向的扫掠都放进 L6，用 OpenCascade 的布尔求交和最短距离来算。
  • 内核会建失败，官方文档建议圆角放到最后做。建不出来记 L0 失败，算在模型头上。
  • build123d-mcp 对导入的 STEP 做特征编辑，目前只支持普通通孔改直径；沉头孔、台阶孔要 agent 在代码里改，再用 MCP 的形状比对自查。
  • 版本要钉死。build123d 0.13 要 OCP 8.0，CadQuery 2.8 要 OCP 7.9（OCP 是 OpenCascade 的 Python 绑定），两者不能在同一个环境里共存；想沿用 CadQuery 写的检查器，得单独起环境，或者用 build123d 重写。

屏幕操作留一组小对照，放在六周以后做：v0 只有几道局部题，CAD 那边多是 OpenSCAD 题，凑不出一组。等外壳题和 HEMY 盖板题进库，从 T4、T5 里挑 10 道左右，同一道题用 build123d 代码和 FreeCAD 屏幕操作各跑一遍。FreeCAD 这边复用 CADWorld 公开的虚拟机镜像和评测代码，agent 换成能看截图、发鼠标键盘动作的框架，主线那三个命令行 agent 不直接适用。PCB 这边比 KiCad MCP 和 KiCad 屏幕操作（Cua-Bench 那样）：同一个软件、同一个工程，只换接口，比 CAD 这边干净。这组对照回答 G5，主排行榜只收代码和 MCP 的成绩。每次有新模型发布就重跑一遍，因为 CADWorld 测的还是 GPT-5.4 和 Opus 4.8，屏幕操作的结论可能过时。

§4 题源

文件齐了，不等于对得上

工程文件主要在 GitHub 和立创开源平台。续调研把 25 条项目记录追到了板、机械、固件和制造包这一层，拿到的文件比上一轮以为的多；可版本对得上、能直接当参考答案的组合，比“六类资源都找到了”的项目还少。

去哪里找

  • GitHub 和 GitLab 是主干，许可也最好在这里逐个资产核。搜索的终点从仓库主页挪到能配套的资产链：README、Release、文档外链、子模块。SmartKnob 的整机 Fusion 文件在机械 Release 里，splitflap 的制造包在 Release 链到的 S3 上，IronBen 的固件源码在子模块锁定的旧提交里，默认分支已经没有了。所以“没找到”只代表所查的位置没有。
  • oshwhub（立创开源平台中文站，国际站叫 oshwlab）适合发现项目。续调研用登录的浏览器逐个核过项目页、附件和在线编辑器，能把原生工程导出到本地，比如瀚文的 11 块板、Roboto 的 3 块板。页面刚打开时会短暂显示“暂无 BOM”，要等加载完再记。平台协议对批量获取和 AI 训练用途有限制，见本节末尾。
  • Kitspace 和 OSHWA 认证目录是现成的索引，但清单可能指向已经不存在的文件，Glasgow 的 revC3 BOM 就是一例。Crowd Supply 的发货记录、Hackaday 的报道、PCBWay 的买家评价可以当实物证据。Printables、MakerWorld 只能补外壳。

参考工程自己也有错

AlkaidMount 的两个贴片坐标文件都是 0 字节；HEMY 底座法兰小板的 BOM 只有表头；LumenPnP v4.2 的发布包缺了源工程里的两层内铜，也没有主板 BOM；Glasgow 的打印外壳作者只在 revC1 上测过，量产的是 revC3。同一个仓库里的板、壳和固件，也可能来自不同修订。

许可和平台条款

gym 只做学术研究，禁止商用（NC）的许可不构成排除理由，ToddlerBot 的 CC BY-NC-SA 这类可以用。题源调研（10-24）据此认为学术用途都能入库，续调研撤回了这个结论：学术用途只解决了商用这一条，获取渠道、资产许可、拟用用途和再分发方案还要分开记，一样推不出另一样：

  • 获取渠道。oshwhub 的项目授权许可协议（页面标 2026-08-18 生效）第 3.5 条，限制未经书面许可的自动批量获取，也限制把这样拿到的内容用于数据分析、机器学习和 AI 训练。手动能打开、能导出，不等于能拿来批量建训练集；手动导出的单个工程能用到什么程度，按协议 3.1 条看项目自己标的授权，续调研没有替平台下结论。所以优先走作者的官方仓库；只在 oshwhub 上有原生工程的项目（瀚文、Roboto、嘉立创官方机器狗），要另取平台授权，或者先只当发现入口。
  • 资产许可。同一个项目里，不同资产的许可可能不同，要按文件记。OpenFlexure 的机械和主板是 CERN-OHL-S-2.0，固件是 GPL-3.0，照明板是 CERN-OHL v1.2；瀚文的 oshwhub 项目选了 Public Domain，GitHub 是 GPL-3.0，平台页脚又写学习交流、非商业，三种说法并存，我们不替它裁决。
  • 相同方式共享。GPL、CC BY-SA、CERN-OHL-S 这类条款，公开发布衍生数据时要沿用同一许可，带 NC 的也要继续标 NC。
  • 其他。没找到许可证的（Dummy）只存链接和提交哈希。Fusion 360 Gallery 不能整体再分发，也不能把模型关联回原作者；Onshape 的条款禁止爬虫和数据挖掘。数据手册有版权，只发料号、URL 和抽出来的事实。KiCad 论坛上有人公开反对拿项目做 AI 训练，原话是 “AI training IS NOT research”。留一个退出机制，成本很低。

以上不是法律意见。

§5 出题

以改需求为主，先写契约再出题

完整工程用来采集，出题时只截其中一块：从资源图里取一块能独立验收的变化，比如一块接口板、对应的盖板和安装基准，题目只声称它实际测过的性质。

为什么以改需求为主

从零做的 PCB 题几乎全是零分。Cua-Bench 的 25 道 KiCad 题里有 16 道要从零画原理图，参评模型一道都没全对，最好的模型做对的 6 道都在其余 9 道里（其中有改元件值这类修改题）；PCBWorld 的中等板（只测了 10 块）上，所有 LLM 都是 0 分。全零的题分不出模型高下，也给不了训练信号。改已有设计更容易拉开差距：CADEngBench 里改已给的 CAD，通过率是 59.3% 到 72.3%，从零建模并在参数扫描下保持不变量的题只有 6.3% 到 41.4%。

改需求也最贴近爱好者改开源项目的真实用法。原工程只是参考候选：需求一改，它不一定还是正确答案，所以每道新需求题都要先有人做出一份满足契约的解，再加一份独立的替代解。判分按需求写检查，允许多种正确解。要不要加从零设计的题，看试跑的通过率和失败分布再定；简单题不全筛掉，大量全零的题也不当成“更难、更好”。赤道仪案例是另一回事：它先当工具包的演示，让 agent 在人看着的情况下从需求画到下单，每次人工介入都记下来。等这条路能少靠人跑通，就照它的样子出 T7 金任务。

T7 金任务：少，但不能没有

T7 是上面“看试跑再定”的例外，试跑之前就定下要有：它是唯一能测整条链的题，也是唯一能拿实物结果给判分器算误收和漏检的题。题目是从需求做出一件能通电的完整小产品，比如一块可调降压电源模块配上外壳。

  • 分八关。需求和规格、选型和 BOM、原理图、PCB、制造包、外壳和装配，这六关自动判，照常计分；下单打样、通电和试装两关由人按事先写好的测试脚本做。
  • 只给六关全过的方案打样，每题每个 agent 至多一个，取第一次全过的运行。一轮两三道题，连人类参考在内大约 10 次打样（估算，没询价）。
  • 实物次数少，算不出可靠的通过率，所以实物结果单独报告，当案例研究和判分器的校准数据，不进主排行榜。
  • 入库条件另算：维护者先把参考解完整做一遍并打样通过，替代解只要求过前六关。
  • T7 不进 v0。赤道仪案例是第一个原型；第一批正式题最早放进六周以后的增补，选哪几道，和打样预算、测试仪器一起定。

真实修订是最好的题源

作者自己写明原因的修订，比随手删线、挪孔更像真问题。Corne 从 v4.0 到 v4.1，因为原来的电源座缺货，换成了 PJ-399B-6A，电路、固件和外壳都要跟着改（v4.1 发布说明）；HEMY 作者说 v2 可以换用 OnStep 社区的 MaxPCB4 主板，但要改顶板和开孔（讨论 #23）；瀚文在 oshwhub 上同时留着主控板“有 BUG”和“已修正”两版，差在哪还没核。用法是旧版加新需求当起始状态，新版当参考候选，再按需求验收，不要求和作者的补丁逐字节相同。北大有一个同名的 HWE-Bench，做的是芯片 RTL 代码修复，和第 1 节那个板级基准不是一回事。它就是这样从真实 PR 筛题的：从 6 个仓库的 3 万多个 PR 里筛出 417 题，坏版本测试失败，打上参考补丁后通过，再人工审。要注意两点：作者的提交常混着无关改动，只抽出独立的需求；PCB 和 CAD 项目很少有回归测试，每个修复都得补检查。

制作顺序：先把 A 和 D 各做成 3 到 5 个故障位置或参数不同的实例，再做 B 和 E，最后做 C。同一项目族的实例全部分在同一边；五个项目做出再多变体，也只算五个独立项目族，不能拿变体数充题源的多样性。

这些都是局部题，G1 说的整条链不会一步到位。B 这类题已经跨了 PCB、外壳和制造包三段，赤道仪案例会让 agent 从需求一路做到打样。等每一段的检查都校准过，再把局部题串成从改需求一直做到新下单包的长题。

从工程到题目的九步

  1. 冻结工程。固定每个仓库的提交、子模块、Release 附件和云端 CAD 版本，顺着 README、Release、文档和附件外链找全。留下项目清单、下载哈希、资源关系和缺失清单。
  2. 闭合依赖。收齐层级原理图、符号和封装、3D 模型、CAD 引用的库、固件依赖和加工参数，查 LFS 指针和空文件。依赖不闭合的，不进“可重建”的题池。
  3. 跑原版基线。用固定的工具镜像打开、重建、导出，原工程本来就有的问题逐项记豁免，不默认开源工程 DRC 为零。嘉立创 EDA、Eagle、Altium 转 KiCad 只是可选做法，转的话要核对转换前后的连通、封装、层叠和坐标。
  4. 写需求契约。写清目标变化、要保持的东西、可改的文件、交付物、单位和容差、允许哪些等价实现；分清作者原有的要求、从几何或电路量出来的接口、出题人新加的要求。“板上有个圆孔”推不出它必须是 M3 固定孔。关键数值没冻结的，题目留在草案。
  5. 生成起始状态。删一部分设计、注入一个能归因的故障，或者给旧版加新需求；去掉参考产物。原样提交必须不达标。
  6. 做参考解。由合格的人做出至少一份满足新契约的解，再加一份独立的替代解。需求变了，旧工程不一定还是正确答案。
  7. 校准判分器。参考解、替代解、单故障、组合故障、容差内外成对的样本都跑一遍，再加空输出、删掉整面墙、旧网表、改规则、偷读参考答案这些攻击样本；题面数值和检查常量逐条对账。
  8. 按项目族划分。fork、remix、同一项目的不同修订、同一个参数母体，归成一族，再分训练集和测试集，同族不跨边。
  9. 发布接纳。冻结题面、环境、起始状态、判分器和预期检查；记下每一步的存活数和淘汰原因；能不能发布、能不能拿来训练，单独标。

一道题要进题库，得同时满足：资源和依赖能重建；题面数值完整；必需检查都能执行；参考解和至少一个合理的替代解通过；原样提交和关键故障失败；候选改不了测试；用途和分发状态写清。缺一项，就写明原因，留在草案里。论文里同时报采集了多少项目、资源完整的有多少、能重建的有多少、能出题的有多少、最后接纳了多少题，以及每一步的淘汰原因。

§6 判分

“验证过”要拆开记，判分器也要先体检

确定性的检查也会写错。续调研在已发表的基准里找到了题面和检查对不上的例子；EDA Bench 换了更严的判分器重算同一批输出，最高加权分从 4.58% 掉到 1.48%。所以不写一个笼统的“已验证”，每条结论都说清验证了什么。

几条规矩

  • 上线前过三组样本：参考解、等价的替代解、故意做坏的近似件。只看参考解满分、明显的坏例低分，证明不了判分器可靠。EDA Bench 的旧判分器让 35 个参考解全得 1.0、35 个严重故障都不超过 0.15，看着很好；修订稿换上更严的检查后，参考解平均 0.957，有 2 个只得 0.25；删掉一个无源件的 34 个故障样本，只有 11 个降到 0.75 以下；一个合理的 0.35 mm 统一线宽被打到 0.25。体检做得最完整的有三家，CAD-bench 是其中之一：审计里参考件得 0.992 分，独立写的替代件 0.896，近似故障件还有 0.684。
  • 原样提交必须判挂。CADGenBench 的编辑题里，把输入原样交回也可能拿到 0.4 分，所以要单设一道“目标变化有没有发生”的二值门。
  • 题面和检查要对账。CADWorld 有一题，题面要求把 12 mm 的边放大到 18 mm，检查却还按 12 mm 算体积。题面数值、检查常量和参考件的实测值要自动比对。
  • 请人分层盲审。PCB 侧做得最完整的是 PCBSchemaGen：一位资深设计师盲审 300 个输出，判分器和人的一致度 κ 0.91；判为通过的里有 6.7% 其实是错的，判为失败的里有 2.7% 其实是对的，后者 75% 来自 ERC 过严。它按 50/50 分层抽样，这两个比例不能直接搬到别的题上。误收更危险，错板子会被当成对的拿去下单。
  • 发布后继续抽查判为失败的轨迹。一项审计复核了 5 个屏幕操作基准的 150 条失败轨迹，其中 10.7% 是评测器判错了。
  • 判分器和参考答案不给 agent 看，从最终的原生文件重新导出再判。Cua-Bench 的任务脚本先找现成的网表文件，找不到才从原理图导出，旧导出文件可能掩盖没保存的改动；Cua-Bench 报告里，9 次自称完成的运行有 5 次没过验证；Long-Horizon 里有 agent 改了工艺库的温度系数，还把器件并联数设成 10,000。
  • 执行失败记零分。Text2CAD-Bench 第 4 级只给执行成功的样本打分，结果无效率 17% 和 55% 的两个模型，总分几乎一样（8.20 对 8.26）。评测环境自己出错单独记，不算到模型头上。
  • 固定容差、环境和版本。百分比容差放在 100 mm 的外壳上就是 1 mm；OpenCascade 版本不同，分数就不可比；同一个模型换个 agent 框架，通过率能从 24.6% 变成 0%（Seldon，一个专家出题的 CAD 基准）。判分器修了要升版本、重算旧结果。

怎么计分

每道题输出三样：是否通过、逐项结果、诊断信息。“是否通过”只看声明为必需的检查是不是全过；逐项结果给每条检查的证据；诊断信息给几何距离、错误数、耗时和花费。排行榜只看是否通过：每题每个 agent 跑 3 到 5 次，报单次通过率和它的 95% 区间，以及几次里至少过一次的比例（pass@k，k 是实际跑的次数）。同一项目族的变体高度相关，区间按项目族整族重抽样来算（聚类自助法），不按运行次数算；区间重叠的不排先后。部分分只做诊断和强化学习奖励，不能让“文件很多”“形状很像”抵消短路、错的引脚表或必需的机械干涉；部分分的权重等 v0 校准完再定，和判分器版本一起公布。优化类的题先过硬约束，再比成本和线长。源工程坏了、评测环境坏了、模型交的东西坏了，三种分开记账。另外记三样：成本（BOM 加打样估价）、agent 的花费（token 和时间）、证据质量（引脚和参数决定有没有引用到正确的手册页）。T7 的实物结果单独报告，不进排行榜。

RWE-Bench：哪些做法一致，还能借什么

Xplore 10 月 27 日发布的 RWE-Bench（Real World Engineering）和本节的思路基本一致。官网直接写明的是做法：20 道题分机械、电气、航空航天三类，每个模型用自家的 agent 框架、开最高推理档。三道例题是：三缸柴油机的整体曲轴，要在 2,400 转满载下满足应力、刚度、轴承载荷和疲劳要求；从 Zynq-7000 到两颗内存的 DDR3L 布线，8 层板、71 个网络，约 300 个器件位置固定，已有的器件和走线不许动，要满足等长和阻抗；高压涡轮导叶的换热 CFD。判分全自动，没有 LLM 评委，也没有人工评分；判分程序会跑物理求解器，所有指标都满足才算通过。每道题由一位工程师连同判分器和一份参考解一起写出，参考解用的是 agent 拿到的同一套工具。

结果的数字大多是二手的。官网图表是动态加载的，没能直接抓到，静态文字能核对上的只有三条：Sol 每次运行约 10 美元，Astra 比 Sol 高 12 个点，Opus 高 4 个点，这两个模型的花费都接近 Sol 的 6 倍。RuntimeWire 10 月 27 日的报道和 CADFrontier 10 月 28 日的转录都说有 11 个模型参评，单次通过率最高的是 GPT-6 Astra，37%。下面这些只见于 CADFrontier：20 题是机械 9、电气 5、航空航天 6；每题跑 5 次，每次最多 24 小时，共 1,100 次；Claude Opus 5.5 是 29%，GPT-6.1 Sol 是 25%；5 个模型一次都没过，4 道题没有任何模型做出来；每题 5 次里过一次就算的话，Opus 5.5 是 70%；平均每次跑 3.4 小时，跑得久的分数并不更高。

一段中文新闻转述（原始出处没找到）大体准确，一处说过了头，一处查不到出处。说过头的是“直接操作专业工程软件”。这句照搬了官网的宣传语（“the same CAD and CAE tools used by professional engineers”），但“直接操作”容易让人以为是点图形界面；官网点名的只有曲轴例题用的 CadQuery、Gmsh、CalculiX 和 Python，其他题用什么工具没写，CADFrontier 也指出这不是 SolidWorks、NX、Creo 这类交互式参数化软件。查不到出处的是“Astra 5 次通过率 60%”：官网静态文字和 CADFrontier 里都没有；官网有一张 pass@k 动态图没抓到，所以只能算未核实，不能说写错了。读它的分数还要记住 CADFrontier 提的几点：题少，前两名的区间重叠，名次不算定论；题、判分器和参考解都不公开，外人没法复现；分数是模型加自家框架一起的结果；Xplore 本身卖强化学习环境。

借过来

  • 所有硬指标都满足才算对，每条指标写成带阈值的数：质量、应力、疲劳、等长、阻抗。本节已经这样定，需求契约里的每条要求都要能这样算出来。
  • 参考解用 agent 拿到的同一套工具做出来，证明题在这套工具里做得出。SolidWorks 可以拿来核验，但不能替 build123d 题做参考解。
  • 每题多跑几次，报单次通过率的区间和 pass@k，旁边列每次运行的花费和时长。题少时名次往往定不下来，所以要画区间；区间重叠的不排先后，区间的算法也要写明。
  • 没人做出来的题照样留着，只要有参考解证明能做。T7 金任务也照这个思路留：题少、难，但参考解要有实物证明做得出。
  • 评测题不授权训练，官网原话是 “The benchmark tasks themselves are never licensed for training”，训练环境另出。我们按项目族分开，测试用的项目族不进训练。
  • 电气题也能这样判。DDR3L 那道例题用的是等长、阻抗这类确定性检查；“已有的器件和走线不许动”也正是 T5 的出法。高速板本身 v0 先不碰。

补上它没做的

  • 判分器的体检结果要公开：参考解、替代解、故障样本各过了多少，盲审的误收和误拒是多少。RWE 没公开这些。
  • 检查代码随工具包开源，再留一份公开的开发集，外人能复现开发集上的分数。开发集从不进测试集的项目族里出，比如本来就要公开演示的 HEMY 一族；测试题的题面、契约常量、参考解和故障样本都不公开。
  • 模型和框架分开看。除了各家自己的框架，六周以后再用同一个简单框架把所有模型跑一遍。gNucleus 的 CAD Bench V3 榜上有同一个模型配两种框架的分：Opus 5.5 配 Claude Code 是 61.03，配 mini-swe-agent 是 57.96（百分制的平均奖励，不是通过率）。

SolidWorks 2025 怎么用

项目手上有一台装了 SolidWorks 2025 的 Windows 电脑。它进不了 gym 的评测环境：要 Windows 和授权，装不进容器，也没有官方 MCP。但在评测环境之外，有三处用得上，前两处可以离线批量跑，第三处靠人。

  1. 转题源。第 4 节里 Solo（89 个原生文件）、Roboto Origin 和 AlkaidMount 的机械源都是 SolidWorks 格式。用它打开、重建，记下有没有重建错误，导出 STEP，量出质量属性和关键尺寸，补进资源图。外壳题照旧在 STEP 上出，参考解用 build123d 做，SolidWorks 只拿来核验。
  2. 交叉核验判分器。L6 用的是 OpenCascade，SolidWorks 用的是另一套内核 Parasolid。给判分器体检时，把参考解、替代解和故障样本的 STEP 导进 SolidWorks，跑干涉检查，量体积和质量属性，和我们的结果逐项对。两套内核对不上的样本都要人工看，原因可能是容差、STEP 转换，也可能是判分器的 bug。
  3. 人工盲审和金任务终检。审阅者在 SolidWorks 里打开候选的 STEP，量尺寸、剖切看间隙；T7 金任务下单前，再用它做一遍干涉检查，CNC 件加跑 SolidWorks 自带的 DFMXpress 可加工性检查。

批处理走它的 COM 接口，用 Python 的 pywin32 调。开源的 pySldWrap（MIT）包好了打开、改尺寸、重建、导出 STEP 和读质量属性，不过它停在 2022 年的 0.2 版，没在 2025 上试过；干涉检查用装配体的 InterferenceDetectionManager。按 TriMech 和 GoEngineer 两家经销商的版本对比，干涉检查、质量属性、SimulationXpress（单零件的简易有限元）和 DFMXpress 在 Standard 版就有，零件和装配体的完整有限元、运动分析要 Premium。转格式和查干涉，商业版哪个都够，教育版的功能范围没查；想拿它给金任务做装配体有限元，就得是 Premium。

§7 产出

一篇基准论文，加一个真有人用的工具

论文靠任务定义和验证器立住，工具包靠能复现的实物 demo 传开。

论文要回答的四个问题

  1. 今天的 agent 沿整条链能走多远，卡在哪类检查上？
  2. 同一批题，走代码和走 MCP 差多少？屏幕操作在同题对照里差多少？
  3. 验证器能在下单前多拦住多少错，代价是多少误收和误拒？
  4. 验证器分数当奖励，能不能把硬件设计能力训上去？

主贡献是任务定义加验证器（G1、G2、G4）。建题方法本身也能写进论文：从完整工程建资源图、写需求契约、生成会失败的起始状态、校准判分器，并公布每一步的存活数和淘汰原因。附加的有：接口对照（G5）；一个新指标，看每个引脚和参数决定有没有引用到正确的手册页（G3）；小规模实物子集（G7）；可训练。已有工作说明验证器分数当信号有用：PCBSchemaGen 用它引导推理时的搜索，cadrille 和 CADEvolve 用几何奖励做强化学习，都有明显提升。

投稿方向：NeurIPS 的数据集和评测赛道（基准本体；EDA Bench 的修订稿用的就是这个赛道 2026 年的模板）；ICLR（PCB-Bench 发在 ICLR 2026）；MLCAD（PCB-QA 发在这里）；DAC、ICCAD（EDA 圈）；KDD 的 agent 评测研讨会（PCBWorld 发在这里）。加上新手用户实验的话，也可以投 CHI 或 UIST 的个人制造方向。

热度：几千 star 比较现实

学术基准的仓库一般只有几十到几百 star（PCB-Bench 45，3DCodeBench 96）。KiCad、FreeCAD 的 MCP 各约 2.9k，是比较现实的对标。给创作软件接 MCP 的项目里最火的 blender-mcp 是 2.8 万，要到这个量级，得有几个别人能照着复现的 demo（赤道仪、墨水屏手表、机械键盘这类），第一次下单的成功率也要够高，这一点没有把握。

有利

  • 实物比软件好传播。一块点亮的板子、一台自己做的赤道仪，比反编译截图直观。
  • 嘉立创体量大，也有动力。2026 年上半年嘉立创 EDA 注册用户 736.88 万，订单 1,163.94 万笔，CNC 收入同比增长约 110%；它的官方博客已经在写 Claude Code 画板实测。
  • 中文社区有需求。B 站有从 MCP 配置讲到嘉立创 EDA 实战的教程，也有人在卖技能包。

不利

  • 硬件试错花钱、要等，失败会被放大。OpenAI 的 KiCad 演示在 Hackaday 评论区和 KiCad 论坛招来不少质疑：走线乱，读不准手册，画不好封装。
  • 少了 REA 那种“能抄别人软件”的争议，话题性弱一些。
  • KiCad MCP 已经有好几个，单做又一个 MCP 不会火。

§8 路线图

前六周：先做工具包和赤道仪，第 3 周起建题库

验证器从第 1 周就写进工具包。赤道仪案例跑出第一批失败、检查规则有了雏形以后，第 3 周开始建题库，用的是同一套验证器。这样规则从真实失败里长出来，题也更像真问题。

时间做什么怎样算完成
第 1 到 2 周把 KiCAD-MCP-Server、jlcparts、easyeda2kicad、Freerouting、build123d-mcp 串起来；写 L0、L1、L3、L5、L6 检查和证据记录，外加 L4 里最简单的功率回路长度检查（赤道仪是电机驱动板，这一项必须有）。拿一个带嘉立创下单包的成熟项目（比如 Corne v4.1，BOM 和坐标文件的 164 个位号对得上，坐标和旋转还没核），从需求跑到下单包，各类检查都出结果，每个器件都带手册链接和料号快照。
第 2 到 4 周谐波赤道仪案例。先把 HEMY v2 自己的源工程和制造包对齐：主控板的源是 4 月的、制造包是 6 月的，两块小板的 BOM 有缺项。这些差异先核实是不是真错（比如缺的是不是手焊件），核实了的就是 agent 的第一批真实修复题。再参照 HEMY v2 的方案（OnStepX 固件、两颗 TMC5160 步进驱动），让 agent 从需求做到驱动板、外壳和嘉立创下单包，真打样一次；补上 L4 的降额核算，接入 PCBSchemaGen 验证器做 L2；全程录屏，记下每次人工介入和失败原因。板子回来能上电，电机能转。产出 demo 视频和论文里的案例研究，失败清单变成新的检查规则；对齐好的 HEMY 工程留给题库。这一轮也是 T7 金任务的第一个原型。
第 3 到 6 周v0 题库。先做 OpenFlexure、Corne、splitflap 三个项目族，每族 2 到 3 道局部题，参数编辑、PCB 和外壳联动、制造包一致性各至少一类。A 和 D 先各做 3 到 5 个实例，实例是同一道题换个故障位置或参数。HEMY 的燕尾板加盖板题等工程对齐后再加：第 6 周前校准过就进 v0，赶不上就放进六周以后的第一批增补。每题交付冻结的资源图、可重放的参考解、会失败的起始状态、需求契约、独立的替代解、故障样本、校准报告和隔离的判分器。跑 Claude Code、Codex、Gemini CLI，每题跑 3 到 5 次，报单次通过率的区间；做接口对照（代码对 MCP，先在卡 D、卡 E 的板子部分上比）和装不装工具包的对照，抽一批结果请人盲审。每道题都有校准报告：参考解和替代解通过，原样提交和关键故障失败。第一版结果按题族报告，附每一步的候选数、存活数和淘汰原因。
第 6 周开源工具包和检查代码，发技术报告和 v0 题库的校准报告（测试题不公开；公开开发集用 HEMY 一族的题，赶不上就随第一批增补发），在 B 站和 X 上发 demo。对外发布。

先别做的事

  • 高速板、射频、BGA、市电，先都不碰。
  • 别自己写布线算法。Quilter 和 PCBWorld 在做这件事，Freerouting 够用。
  • 别急着扩项目数。先把三个项目族的题校准好；拿变体数充题量，也撑不起多样性。
  • 别只发排行榜。排行榜能拿到报道（EEBench 上了 Hackaday），让人用起来的是一条命令就能装的工具。

§9 风险

主要风险和对策

风险对策
被模型进步追平。EEBench 官方榜单（10-14 的快照）上，同为 Sonnet 档，4.6 得 20.4%，5.5（xhigh 推理档）得 67.2%。画原理图、布线这类单点能力，大概率会被模型进步和大厂产品覆盖。多出长流程、跨领域、改需求类的题；保留私有测试集；把接口当变量，结论不容易过时。
屏幕操作的结论过时。CADWorld 只测到 GPT-5.4、Opus 4.8 这一代，新模型点 CAD 软件可能好很多。六周以后做一组同题的屏幕操作对照，新模型发布就重跑；追上代码路线的话，再把屏幕操作加进主线。
代码 CAD 交不出原生特征树。用 SolidWorks、Fusion 的工程师要能接着改的模型，CADWorld 作者也拿这一点批评脚本建模。认下这个代价。交付 STEP 加源码；题面要求关键尺寸写成具名参数，判分时改一两个参数重建，确认源码真能接着改；原生格式的题源先转成 STEP 再出题。
被大厂或嘉立创直接做掉。OpenAI 在推屏幕操作；atopile 有 EEBench，还有一个做 agent 训练环境的项目 Aletheia；Flux 融资约 3,700 万美元，9 月底上线了外壳功能；嘉立创有用户、器件库和下单入口，条件最好。做大模型公司没动力做的部分：嘉立创和立创商城的落地细节（库存快照、贴片方向、下单格式）、板壳联动检查、带实物结果的评测数据。和嘉立创更可能是合作关系，工具包保持 KiCad 和嘉立创 EDA 两边都能用。
工具包只是“方便”。REA 被实测过，不装它的普通 agent 反而先完成任务。发布时带对照数据：同一批题，装和不装工具包，下单前拦下的错误数各是多少。打样失败率要等实物子集攒够样本。
判分器误收，或者把错的契约写死。三组样本体检；题面数值、检查常量和参考件实测值对账；分层盲审，论文里报误收率；判分器修了就升版本、重算旧结果；用实物结果校准。
题源本身有错。坐标文件 0 字节、BOM 只有表头、同名的板壳固件来自不同版本。入库先查文件有没有有效内容、版本配不配套；参考工程先跑基线，原有问题逐项记；没证实的配套关系记成版本未对齐，不在上面建题。
平台条款和许可。oshwhub 的协议限制自动批量获取，也限制把这样拿到的内容用于数据分析和 AI 训练。优先走作者的官方仓库；获取渠道、资产许可、用途、再分发分开记；oshwhub 独有的工程另取授权，或者只当发现入口；没有许可证的只存链接；留退出机制。
安全。只做低压直流（比如 24 V 以下），不碰市电和大电流锂电充电；检查里加上极性和保险丝。
可复现。库存每天在变，工具版本会漂，网页上的原生工程也会变。冻结器件库快照；KiCad、FreeCAD、OpenCascade 的版本固定在容器里；网页工程只认导出到本地的文件哈希。
实物成本。墨水屏手表板 5 块贴好片 130 欧元，每块约 26 欧元。实物子集控制规模。

术语

agent
能自己调用工具、分多步完成任务的 AI，比如 Claude Code、Codex、Gemini CLI。
MCP
Model Context Protocol，让 agent 直接调用软件功能的标准接口。
skills
写给 agent 看的分步骤操作说明，用到时才加载。
屏幕操作（CUA）
agent 看截图、点鼠标、敲键盘来操作软件。
build123d、CadQuery
两个用 Python 写代码建模的 CAD 库，底层都是 OpenCascade 内核，能生成精确实体、读写 STEP。build123d 由 CadQuery 的部分代码改写而来，现在是独立项目。
OpenCascade、Parasolid
几何内核，负责算实体、布尔运算和距离。OpenCascade 开源，build123d、CadQuery、FreeCAD 都用它；Parasolid 是 SolidWorks 用的商业内核。
原生特征树
SolidWorks、Fusion 这类软件记下的建模步骤，工程师能回到某一步改尺寸再重建。STEP 不带它。
gym
一组任务加自动判分，既能当评测基准，也能当强化学习的训练环境。
ERC、DRC、DFM
ERC 查原理图的电气规则，DRC 查 PCB 的线距、孔径和连通，DFM 按工厂的工艺能力查设计能不能做出来。
Gerber、BOM、坐标文件
PCB 厂用的光绘文件；物料清单；贴片机用的每个元件的位置和角度（也叫 CPL）。
拼板
几块小板拼成一块大板生产。同一个位号会在每个板实例里各出现一次，这是合法的。
STEP、STL、F3Z
STEP 是精确的实体模型，能量尺寸、能交给 CNC；STL 是三角网格，只能打印或粗查干涉。两者都不带建模历史。F3Z 是 Fusion 360 的归档文件，带建模历史。
DNP
Do Not Populate：原理图和 BOM 里有、但不贴装的器件。
IoU、Chamfer 距离、AUC
前两个衡量两个形状重合多少、差多远；AUC 衡量一个分数区分对错的能力，0.5 等于瞎猜，1 是完全分开。
资源图
把一个项目的电路、机械、固件、制造包和实物证据按版本存成节点，用“由谁生成”“能不能配”“实测于哪一版”这类有依据的关系连起来。
需求契约
一道题的验收条款：目标变化、要保持不变的东西、可改的文件、交付物、单位和容差。
起始状态、参考解
起始状态是交给 agent 的初始工程，原样提交必须不达标；参考解是证明题有解的一份合格答案。
项目族
fork、remix、同一项目的不同修订归为一族。划分训练集和测试集时整族一起走。
降额
器件在实际工况下的参数比标称值差，比如陶瓷电容加上直流偏压后容量明显下降。
SPICE 公差角
把元件参数推到公差上下限的各种组合去仿真，看最坏情况下电路还能不能工作。
误收、误拒
判分器把错的判成对，或者把对的判成错。各家论文的分母不一样，引用时要写清。
κ
扣除偶然一致后的标注一致度，1 是完全一致。
pass@1、pass@k
pass@1 是单次运行的平均通过率；pass@k 是每题跑 k 次、至少过一次就算这题过。
95% 区间
按样本推出的范围，真实通过率有 95% 的把握落在里面。同一项目族的变体高度相关，Omnifex 按项目族整族重抽样来算（聚类自助法）。两个模型的区间重叠时，不排先后。
有限元、CFD
有限元把零件划成小网格，算应力和变形；CFD 算流体流动和换热。Gmsh 负责划网格，CalculiX 是开源的有限元求解器。
金任务
T7：从需求做出一件能通电的完整小产品，比如一块电源模块配上外壳。前六关自动判，只给全过的方案打样，通电和试装由人做；结果单独报告，不进主排行榜。数量少，但题库里不能没有。
canary 字符串
嵌在题里的唯一字符串，用来发现题目有没有混进模型的训练语料。
OnStepX、MaxPCB4
OnStepX 是开源的望远镜赤道仪控制固件，MaxPCB4 是 OnStep 社区的一款主控板。TMC5160 是 HEMY 用的步进电机驱动芯片。
燕尾板
HEMY 燕尾座上的 DC 和 USB 接口小板，工程里叫 ZZ - DC & USB Dovetail。
Sangaboard
OpenFlexure 显微镜的电机控制板。
嘉立创、立创商城、oshwhub
嘉立创做 PCB 打样、贴片和 CNC；立创商城是同一集团的元器件商城；嘉立创 EDA 是它家的在线 EDA；oshwhub 是它家的开源硬件平台，国际站叫 oshwlab。
G、L、T 编号
沿用调研报告：G1 到 G7 是七个空白，L0 到 L6 是七类检查，T1 到 T7 是七类题型。
Make Anything
调研报告里给工具包起的名字，本页统一叫 Omnifex。
