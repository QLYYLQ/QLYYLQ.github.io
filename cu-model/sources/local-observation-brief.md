# 局部观察训练路线（精简版）

2026-11-01，11 月 3 日更新。完整版是同目录的《局部观察训练路线梳理》，数字的出处和推理都在那里；上下文衰减测试的步骤在 `局部观察训练路线梳理_notes/上下文衰减测试_todolist.md`。学生模型按你定的：8B、30B-A3B 这一档，解码不低于每秒 250 个 token，每屏不做长推理。

## 主张

论文要证明小模型在长程网页任务上通过率更高。动机是上下文衰减：好的 CUA 不能靠 256K 到 1M 的上下文硬扛。界面是给人用的，版面可预见，模型应当自己学会只看、只记会变的和跟任务有关的区域，这个能力训进参数，不靠外挂。predict 是主角；事后压缩历史（每步照常看整屏，做完把截图换成粗图加一块局部图存进历史）只当对照，本文方案必须在上下文不多用的前提下通过率赢它；latent action 是次要模块，单独消融。

## 每一步怎么做

动作发出后、下一屏到达前，模型写 predict：一个或几个 0 到 1000 的框，加上要找什么，读值步再加一句应该看到什么。下一屏到了，只把框里的原图裁给它看，没有缩略图；没见过的布局就写整屏 `0 0 1000 1000`，很抽象的交互页面可能要连着整屏看几次才写得出小框。它先写判定词（普通文字）：找到了就出动作；没找到（页面对，东西不在框里）就补看，在同一张截图上再写一个框；不对（页面状态和期望不符）就纠正，比如返回、关弹窗、改搜索词、等加载。历史里只存模型自己选来看的区域，全部保留，不设丢弃的规则。

## 和视觉 token 对齐

Qwen3-VL 把截图两边调成 32 的整数倍，16×16 像素一个 patch，相邻 2×2 个 patch 合成一个视觉 token，所以一个 token 对应 32×32 像素；我们 1280×720 的截图变成 1280×704，40×22 共 880 个 token。照你的想法，离线搜标签的格子和裁图都对齐到 token。一格多大、局部图怎么送，下面写的是我的倾向，还没定：

- 搜标签用 2×2 个 token 一格（64 像素，20×11 格），搜到后按单个 token 收边。
- 模型写的框在裁图前往外对齐到 token 边界，局部图按原尺寸送，不放大。处理器默认每张图至少 64 个 token，要把这个下限调低。
- 证据包（你 11 月 1 日导出的）13 例放到 1280×704 上：证据框中位数约 17.5 个 token，对齐到单个 token 是 33 个，对齐到 2×2 一格是 48 个。按原尺寸送时，3×3、4×4 切分用的 token 是按 2×2 一格对齐的框的 2.3 到 3.4 倍；每块都放大到 384×384 再送，就没差别了。
- 前提是小块局部图也能读对，要先测。

## 现有证据（都是零样本，样本小）

- 下一步要看的地方可预见：抄刚发动作的位置取 8 格，命中下一次点击 56/111；三个模型只有 19 到 30。
- 历史会干扰：LookAgain-8B（一个 8B 的定位加确认模型）选格，只给当前屏 30/111，加同任务历史 19，加无关历史 13；两个 Qwen 掉得少。
- 给对区域就能读对：连续矩形 48/48。
- 32B 零样本写框 10 条格式全对、判对 5 条；先分析布局再写框，四个模型里三个变差。

## 标签和训练

标签照 VW（VisionWeave）的自监督：冻结的整屏 teacher 看着真实的下一屏，在对齐 token 的网格上，从动作目标框、读值所在的 DOM 节点和注意力热点出发贪心加块，直到只看这些块时动作和看整屏一致，外接框就是标签。到屏幕四分之一还过不了、同一模板在历史里没出现过，或者 teacher 整屏出的动作和录下的不一致，就标整屏。没找到的样本靠挪框自己造；不对的样本来自失败步、分叉和改 DOM。

训练顺序按你定的，先 SFT 加自监督，调好再上 RL：整屏底座（自己采的数据加 AgentNet、WebChain、WebSTAR），再做前瞻训练加 KL 自蒸馏；RL 的细节到时候再定。你问的“写框热身”，现在叫当前屏写框：在已经看得到的当前屏上写出这一步要读或要点的地方的框，标签用 DOM 框，只练框的格式和坐标尺度（8B 零样本 10 条里 7 条把坐标写成 0 到 1 的小数）。我倾向把这类样本混进整屏底座，不单开一个阶段。

## 前瞻训练前先测

用审查（10-29 的《试验性数据采集审查》）里那 30 条完整轨迹，这 30 条不进底座训练。

- 上下文衰减：全历史、最近 4 张截图、最近 2 张、只留文字、无历史，比和录下动作的一致率，按步序看；你按 todolist 在自己的环境跑。更长的历史用 VeriWeb 的人工演示补测。
- 只给对的区域时，动作还和整屏一致吗；局部图按原尺寸、放大、往外扩各送一遍。
- 前瞻的规则基线：抄动作位置、固定中心、随机等。

## 主实验与评测

四行：全保留历史、只留最近几步、事后压缩历史（在压过的历史上训过）、本文方案；报通过率、视觉 token、调用次数和墙钟时间。第 30 步的视觉 token：全保留 26,400，事后压缩 11,436；本文方案每步一块区域、两次整屏时，约 3,100（区域按原尺寸送）到 7,900（区域都是四分之一屏）。30 步里整屏看超过 7 到 12 次就会反超，所以整屏次数要实测。

Odysseys 做主评测（200 个真实网页任务，每个至少跨两个站，各模型平均 42 到 86 步）；WebChoreArena 做可复现的第二套（532 个任务，考记忆和计算）。两套的任务都能在 GitHub 上下到。Online-Mind2Web 加进来当短任务对照（300 个任务，HF 上同意条款后能下）；它的网址也进采集，所以按网站留出约三分之一不采，对照只在这部分上报。VeriWeb 不再当评测。

## 采集任务和底座数据

只用论文说的数据真能在 HF 或 GitHub 下到的来源。核了 12 个采集来源，过关五个，另外加上 Online-Mind2Web 的 300 个任务：

- WebChain：31,675 条真人轨迹，平均约 10 步，CC BY 4.0。
- AgentNet：22,625 条真人桌面任务，平均 18.6 步，pyautogui 动作，MIT。
- WebSTAR：13,338 条 OpenAI CUA 轨迹，每步有评审分；论文的步数口径自相矛盾。
- InSTA：只放了 146,746 个任务，计划步骤平均 4.74 条；论文说的截图和轨迹没放。
- VeriWeb：302 个长任务的完整人工演示，平均 272.5 步。

照你说的，这些任务和网址都拿来多造数据：在不同的步上分叉、同一网址换任务、串 3 到 6 段的长任务（后一段用前一段读到的值），多出同一模板反复出现的数据。小框标签只出现在模板见过的步上，这类数据正好教“看过一次布局，后面少看”。一个能用的分叉决策约是一个能用的录制步的 1.8 到 2.5 倍，下一轮要量准。采集避开 Odysseys 用过的站和 WebArena 的四个站；Online-Mind2Web 留出的网站和 VeriWeb 留来测长历史的 10 到 20 条任务也不采。

## 动作侧

LAR 那种宏符号（把常见的动作片段换成一个新词）按我们的输出格式估，每步最多省 18.9% 的解码（约 38 毫秒），少一次调用约省 1 秒，所以 latent action 要省调用：把多步合成一个，先当消融。

## 已定的事（11 月 3 日）

- 历史里存模型自己选来看的图，全部保留。
- 判定词和需求类型用普通文字。
- 网格和裁图对齐到视觉 token。
- 上下文衰减先测，你按 todolist 跑。
- 先 SFT 加自监督，调好再上 RL。
- Online-Mind2Web 加进来，网址也进采集。
- 外部来源的任务和网址都进采集，分叉、换任务，多造相似布局的数据；VeriWeb 不再当评测。

## 还没定的事（括号里是我的倾向）

- 网格一格多大（2×2 个 token 去搜，最后按单个 token 收边）。
- 局部图怎么送（原尺寸，前提是读得对）。
- 当前屏写框（混进整屏底座）。
- Online-Mind2Web 留多少网站做对照（约三分之一）。
- VeriWeb 留多少任务测长历史（10 到 20 条）。
- 局部图的位置编号（先照常，沿用整屏的行列号当可选消融）。
