# 上下文衰减测试 todolist

2026-11-03。对应《局部观察训练路线梳理》“前瞻训练前先测的三件事”里的上下文衰减那一项，你在自己的实验环境里跑。

要回答的问题：在我们现有的轨迹长度上（10-28 试采平均 15.6 步，全历史约 1.9 万 token），靠后的步里，给模型全部历史截图是否反而不如只给最近几张。是的话，论文的动机在现有数据上就能立住；不是的话，动机主要靠 Odysseys 这种更长的任务来证明。

*标注沿用报告：**项目数据**是项目文件里的数，**推断**是由证据推出的判断，**直觉**是没有直接证据的判断，**建议**是具体做法。*

## 准备

- [ ] 数据：10-28 那轮（`cua-collection-20261028`）的录制在 spectragent 的运行目录里；逐条记录也在验证包的 `records/*.jsonl` 里（Mac 上 `$LOCAL_HOME/QLY/report/cu_model/数据采集验证报告与详细记录.zip`）。
- [ ] 轨迹：用审查第 3.1 节说的那 30 条完整轨迹（约 470 步）。已经抽好的照用，从第一次撞上人机验证那一步起，后面的步都去掉；还没抽的话，从没撞过验证的 476 条里按条随机抽 30 条，记下随机种子。
- [ ] 留出：这 30 条以后不进整屏底座（第一轮用原图做的全量 SFT）的训练集。调提示、解析规则和 judge 用这 30 条以外的几条轨迹，30 条只用来报数。
- [ ] 参考动作：录制模型（`deepseek-v4.1-flash-m17`）录下的动作当参考，主结果只算可信的步。审查第 3.1 节建议过每步审核（审核模型逐步判通过或不通过），做了的话只用判通过的步；还没做，就用机械筛选：`step_status: ok`（动作执行成功）、主文档已加载完（导出器 `exclude_unloaded_steps` 管的那一项）、不在人机验证页上。全部步的结果另报一份。
- [ ] 模型：先用零样本的 Qwen3-VL-8B-Instruct 跑一遍看方向；整屏底座训完后，用同一套脚本再跑一遍，以那次为准。
- [ ] 格式：用 10-28 导出学生样本的那套系统提示和历史写法（验证包第 8 节那首批 46 条学生样本就是这个格式；截图 1280×720 缩到 1280×704，每张 880 个视觉 token）。各设置之间只改“历史里哪些步留截图”，别的都不动。零样本模型先在调提示用的那几条轨迹上跑 20 步，看输出能不能解析；解析率低于九成，就在系统提示里加一个格式示例，所有设置共用这一个提示。
- [ ] 推理：贪心解码；`max_model_len` 要放得下最长那条的全历史（30 步约 3.6 万 token，**项目数据**，留到 6.4 万）；开前缀缓存。记下被截断的提示数，应当是 0。

## 设置

每一步在下面五种历史下各出一次动作。历史用录下的前缀（录制模型的截图、thought 和动作），不用被测模型自己跑出来的；当前屏一律给整屏。括号里是 CSV 里 `setting` 的取值。

- [ ] 全历史（`full`）：历史里每一步的截图都留。
- [ ] 最近 4 张（`recent4`）：最近 4 步的截图留着，更早的步只留文字（thought、动作，以及导出格式里原有的 URL 等文字）。
- [ ] 最近 2 张（`recent2`）：同上，只留 2 张。
- [ ] 只留文字（`text_only`）：历史里一张截图都不留。
- [ ] 无历史（`no_history`）：只给任务和当前屏，当下限，看历史到底有没有被用上。

## 判一致的规则

每个输出和录下的动作比，一致记 1，不一致记 0。先把两边换到同一个坐标系：模型输出的坐标换成原截图 1280×720 上的像素（Qwen3-VL 写的是 0 到 1000 的相对坐标，横坐标乘 1.28、纵坐标乘 0.72；导出格式要是本来就用像素，就不用换）。录制里的元素框是视口像素（DPR 1），本来就在这个坐标系里。

- [ ] 点击：单击、双击、右键要同类；点落在录下动作目标元素的框里就算一致。框来自录制里的 DOM 和无障碍树（AX）信息，几个框重叠时用最小的那个。目标元素没有框的步交给 LLM judge。
- [ ] 输入：输入框是同一个（判法同点击），文字归一化后相同（去首尾空格、统一全半角、不分大小写）。意思相同、写法不同的交给 LLM judge。
- [ ] 滚动：方向相同就算一致，不比滚动量。
- [ ] 按键：同一个键或组合键。先统一写法：审查里回车有 Return、enter、Enter、ENTER 四种写法，全选有 Meta+A、meta+a、Meta+a、ctrl+a；不分大小写，Return 当 Enter，只差 Meta 和 Ctrl 的同名组合（全选、复制、粘贴）算一致。
- [ ] 导航（打开网址、返回、前进、新标签页）：动作类型相同；打开网址时域名和路径相同。
- [ ] 等待：类型相同。
- [ ] 结束和作答：类型相同；答案交给 LLM judge，按任务判是否同样正确。
- [ ] 读值的步：录下的 thought 或答案里写出了从页面上读到的值（数字、名称、日期等），这一步就算读值步。这类步另比被测模型写出的值和录下的是否一致，用 LLM judge。只比动作会偏乐观，这是 10 月 29 日定分辨率时补的一条。
- [ ] 多动作步：主结果比第一个动作；另报全部动作逐个一致的比例。
- [ ] 解析不出的输出算不一致，另记一列。
- [ ] LLM judge：用一个固定的强多模态模型（比如录制模型，或你手上最强的那个），所有设置共用同一个 judge 和提示，judge 看不到是哪种设置出的。给它的输入：任务、动作前的截图（两边的点都画上）、录下的动作和 thought、被测模型的动作和 thought；作答和读值的步再加上两边写出的答案或值。

## 每次调用记一行（CSV）

- [ ] 列：`run_id`（被测模型和检查点）、`trace_id`、`step_idx`（从 1 数）、`n_steps`（这条轨迹的总步数）、`setting`、`sample_idx`（贪心是 0，可选的两次采样是 1 和 2）、`ref_action_type`、`agree_first`、`agree_all`、`read_value_agree`（不是读值步就留空）、`parse_ok`、`judge_used`、`step_trusted`（是否算进主结果）、`n_images`、`visual_tokens`、`text_tokens`、`latency_ms`、`raw_output`。

## 分析

- [ ] 分桶：按步序分成第 1 到 5 步、6 到 10、11 到 15、16 步以后；再按相对位置分前、中、后三段。每桶报每种设置的一致率和步数。
- [ ] 主比较：第 11 步以后的步上，全历史减最近 2 张。辅助比较：同样的步上全历史减最近 4 张，以及后三分之一那一段。
- [ ] 区间：同一批步上配对算差值，按条重抽（bootstrap 至少 1,000 次）给 95% 区间。
- [ ] 另报：每种设置的平均视觉 token 和延迟；全历史和最近 2 张两两之间的动作一致率，看历史多常改变决定。
- [ ] 画图：横轴步序（或相对位置），纵轴一致率，每种设置一条线，带区间。

能分辨多大的差距（**推断**）：30 条约 470 步，第 11 步以后大概一两百步。设置之间有两成的步改变决定时，配对差值的 95% 区间约是 ±0.1，所以小于 0.1 的差距这次测不出来。

## 怎么读结果

- 主比较里全历史更低，差值区间不跨 0：现有长度上已有衰减，可以当论文的动机实验。
- 区间跨 0：现有长度上看不出衰减，动机主要靠更长的任务（Odysseys 上各模型平均 42 到 86 步），下面 VeriWeb 那一项就更要做。
- 全历史更高，区间不跨 0：现有长度上历史有用、还没衰减，动机同样靠更长的任务。
- 无历史和全历史差不多：模型没用上历史，先查提示和格式，不急着下结论。

## 更长的历史（VeriWeb 人工演示）

主结果出来以后做。能不能做，取决于能不能从录屏里切出截图。

- [ ] 数据：HF `2077AIDataFoundation/VeriGUI`（GitHub `VeriGUI-Team/VeriWeb`），302 个任务的人工演示，`data.json` 加录屏，共 86.2 GB。先只下一条。
- [ ] 看 `data.json` 的动作日志有没有时间戳，能不能按时间从录屏里切出每个动作前的截图。
- [ ] 能切的话，抽 10 到 20 条演示（这些任务以后不进采集），比只留最近 k 张截图，k 取 2、4、8、16、32，看 k 变大一致率升还是降。全历史放不下（平均 272.5 步）。
- [ ] 这里的参考动作是人做的，没有 thought，历史里的文字只有动作日志；点击也没有元素框，一律交给 LLM judge。人的动作里有我们动作空间没有的（比如拖选文字），这类步先剔掉。
- [ ] 长度：截图先缩到 1280×720 左右（每张约 880 个视觉 token），k = 32 时截图约 2.8 万 token，加上两百多步的动作文字，6.4 万的 `max_model_len` 够用（**推断**）。不缩的话按录屏的分辨率重算。

## 可选：决定本身有多不稳

- [ ] 全历史设置用温度 0.7 采样两次（`setting` 记成 `full_t07`），算两次之间的动作一致率。设置之间的差距如果和它差不多大，多半是采样的随机性。

## 量

五种设置乘约 470 步，约 2,350 次调用；可选的两次采样再加约 940 次。全历史的提示平均约 1 万 token，最长约 3.6 万，开前缀缓存后 8B 在一张卡上几小时以内能跑完（**推断**）。
