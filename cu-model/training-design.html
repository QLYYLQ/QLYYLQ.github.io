结论先行

  1. VisionWeave（下称 VW）式的自蒸馏适合用来训练前瞻观察。 VW 的监督来自一个问题：丢掉这些视觉细节以后，同一个模型的回答还一样吗？放到 CUA 上，只要采集时把下一屏 O_{t+1} 完整存下（原报告已列为采集要求），而“看哪里”又不改变环境，每条 transition 上任何一种选区够不够用都能离线算出来。单步上，“该看哪里”因此是一个有标签的监督问题，不必靠强化学习去探索（第 6 节）。
  2. VW 的 router 不看任务，原因在输入。 它的 KL 本来就算在当前问题的回答上，只是 router 的输入里没有问题，只能学到训练分布上的平均倾向。loss 可以照用，要改的是选择器的输入：放进任务、历史和刚发的动作。还要有“同一屏、不同需求、该看的区域不同”的对照数据，而且不同的需求要体现在输入里（改写任务，或换一个预声明字段），否则只看图也能把 loss 降下来（6.4 节）。这种对照在真实数据里有多常见，训练前可以先测（实验 E）。
  3. predict 决定三件事：缺什么信息、它会出现在哪里、有多确定。 第一版的“有多确定”用框的大小和是否回退来表达。按 vision encoder 的 patch 切块，很适合当“位置”的单位，也适合在已经到手的帧上按任务挑块。但 predict 发生时下一屏还不存在，“高价值”只能由任务需求加上已经看过的布局来预测，没法从下一屏的 patch 上直接算（第 4 节）。
  4. 第一轮以显式短文本为主，同一份标签再训一个打分头做对照。 选文本是因为便宜：不改模型结构，现有 SFT 栈能直接用，每步决策可读、可审计，约束解码能去掉格式错误。打分头（<predict> 的 hidden state 直接给下一屏每块打分）可能更准：GUI-Actor 在同一个 Qwen2-VL 底座、同一份数据上比较，注意力头在高分辨率的 ScreenSpot-Pro 上远高于生成坐标（40.7 对 15.6），在较容易的 ScreenSpot 上只高一点（88.3 对 85.1）。不过它原本只能指向已经看到的图像，要改造成能指向下一屏的位置。打分头也正好是 VW Stage 2 的对应物。“只看 prefix 能不能预测证据位置”本身，用实验 D 在标签上直接测。放宽时间边界、让模型先看到 O_{t+1} 再按任务挑块会容易得多，但那已经不是前瞻，只当对照（第 5 节）。
  5. 观测合同倾向“粗看整屏、细看选区”。 本次核对的跨领域先例都用或建议用这种结构：360° 视频按预测视角取高清块、同时留低清全景兜底，机器人前瞻预测下一次交互区域，前瞻式注视成像。多分辨率 MLLM 的消融也大多支持保留全局视图。最后仍由 VW 增补的实验 C 定（6.6 节）。
  6. 训练管线要把学习问题拆开，拆成六个。 VW 分开的是三个：表示够不够，选择器能否得到反馈，读取器能否读懂最终表示。本项目还要加上时间边界、任务条件化、知道自己没看到。项目数据在小样本上说明，给对画面就读得对（连续 crop 两个模型都读对 48/48），缺口在选择和充分性判断。管线是：P0 先用实验 B、C 定下合同，冻结后再做诊断；P1 训选择器；P2 在选择器自己选出的画面上训读取器；P3 迭代（第 7 节）。
  7. 第一轮基本不省 token，以后省多少取决于细看的分辨率和历史怎么留。 同分辨率下比，按需观察（每帧细看 10% 的面积，历史只留细看部分）能把 15 步 session 的视觉 token 压到每步整屏的约 1/9。但项目现在已经靠强降采样把每帧压到约 180 token。细看如果用原生分辨率，session 总量反而比现在多（1080p 约 1.3 倍，按项目源图尺寸约 2.4 倍）；按 VW 增补设想的 4 倍像素渲染，历史只留细看部分时能省一半多，历史全部粗看则基本持平。第一轮历史帧不压缩，基本不省；现成 Qwen3-VL 上用“缩略图加 crop”近似还会更贵。1.1 节把减少 token 当直接目标；第一轮的预算口径 Cyrus 已定：每步视觉 token 不超过现在（第 11 节）。
  8. 数据分六类主要数据，外加回归集和人工金标。 六类是：存了原始分辨率 O_{t+1} 的真实 session、转移类型标注、teacher 输出与保真度标签、反事实需求对、不确定与回退样本、读取器适配数据（第 8 节）。需要 Cyrus 拍板的事列在第 11 节。

1. 研究定义（Cyrus 2026-10-20 的整理）

本节照录 Cyrus 认可的 proposal 大意和他对 VisionWeave 的判断，只去掉了引用标记，把人称改成了中性写法。文中的“累计报告”指 COMPREHENSIVE_REPORT_20260929.md。

1.1 根目标：让进入 context 的视觉信息取决于当前任务需求

完成 CUA 任务时，模型不再机械地把每一步的完整截图不断灌进上下文，而是利用任务、已经观察到的内容和当前执行状态，判断下一步真正需要新增什么视觉证据。

“无效 vision token”不简单等于空白、背景或低信息密度区域。一个文字很多的区域，也可能与当前任务无关；一个很小的状态提示，也可能是决定下一步动作的关键。所以目标不只是“同一张图能不能编码得更短”，而是：对于这个任务、这个 session、这个执行阶段，哪些视觉信息还值得进入模型的上下文？

减少 token 是直接目标。在保留任务能力的同时，减少无关或重复视觉信息对长程执行的干扰、缓解 context rot，是进一步希望获得的收益。不能把“token 少了”直接等同于这些收益已经成立。

1.2 原始机制：用已有布局认知，前瞻地决定下一次看哪里

任务 + 已见历史 + 当前屏 O_t + 已发动作 A_t
    ↓
<predict>：预测下一观测中需要看的区域
    ↓
下一屏 O_{t+1} 返回，按预测结果提供视觉信息
    ↓
判断证据是否足够；不够则补看，再回答或行动

做出初次观察选择时，模型还没有看到下一屏。这不是“先把下一屏完整读进来，再找重要区域”，也不是“看完之后再总结”。完整下一屏可以保存在采集侧、用于离线监督，但不能提前泄漏给做预测的模型。

layout 的作用是提供一种可以复用的结构认知，不要求截图完全重复，更不是复用上一次的答案。举个假设的例子：模型此前已经知道搜索结果出现在左侧列表。换一个关键词提交搜索后，它不知道新结果叫什么，却能预计接下来应该读左侧结果列表，而不必重新精读整个页面。

这里要严格分开：可以预测“新证据大概会在哪里”，不等于可以预测或省略读取“新证据的具体内容”。原方案也把 layout 复用当作候选和空间先验，证据是否充分另行判断。因此，预测对象也不是下一次点击坐标：需要观察的地方与需要操作的地方可以不同。

1.3 <predict> 承载的是需要训练的观察能力

<predict> 不是“在 prompt 里加一个标记，让现成模型临时猜一个位置”。希望通过训练，让模型在进入这个预测环节时，能够把任务需求、历史布局与当前状态结合起来，形成下一次观察的选择。真正要学会的是这个条件化的决策，而不是学会输出 <predict> 这几个字符。这也对应累计报告里的一个区分：旧 adapter 学到了协议标记和输出模板，但那不能作为已经学会任务相关选区的证据。

实现层面有一点还没定：special token 在上下文中的 hidden state，是直接控制视觉选择或编码，还是引导模型输出一个观察请求、再由环境执行。目前只确认“这是需要训练的模型能力”，不把它收窄成“只训练一个 embedding 就够了”，也不认定“必须用文本坐标”。

1.4 第一版实现不是研究定义

累计报告后来选择了文本 ROI、[0,1000] 矩形、连续 crop、completion-only SFT，并把 region head 后置。这些是当时的第一版落地选择，不是根目标本身，报告也把它们记作第一版方法设计，还没有验证有效。同样，check/revisit 在原方案里的意义，是承认初次预测可能不充分：模型需要知道自己缺了哪些证据，而不是在没有看到时编出答案。具体状态名、输出 schema 或补看次数，不是 proposal 的本质。

核对用的基准是这一句：

训练一种由任务、session 历史和当前执行状态共同决定的前瞻性视觉信息获取能力：模型借助已经理解的布局规律，在下一观测进入 context 之前，决定需要获取哪些新视觉证据，从源头减少不必要的 vision token 注入；<predict> 是原先设想的可训练机制，而不是研究目的本身。

Cyrus 还没确定的有三点：是否需要显式的 predict；训练哪一部分；predict 的具体逻辑。他最初的想法是直接按照 vision encoder 的 patch 去裁高价值区域。

1.5 对 VisionWeave 的判断

不满足的地方。 原生 VisionWeave 的 router，在图像和配置相同的情况下，不会因为任务或历史不同而改变路由。这是由它的输入决定的，不是多加几档压缩倍率就能解决的。也要避免另一种过度简化：它不是“有字就保留、空白就压缩”的手写检测器。训练时，任务回答的损失确实会影响 router；但 router 自己看不到当前问题，它学到的是在训练任务分布上比较通用的细节分配倾向，而不是每一次任务特有的观察需求。更准确的表述是：它依据“图像里有什么”分配细节；这里希望依据“我正在做什么、已经知道什么、接下来缺什么证据”分配观察。

值得借的地方。 “压缩前后的语义”要按“压缩前后仍能支持相近的理解和回答”来理解：VW 没有要求重建整张图片，也没有要求压缩特征与原始特征逐点相同。它用冻结的原生模型在全细节输入下产生回答，再让压缩输入下的学生在同一回答序列上匹配 teacher 的逐 token 输出分布。监督位置在回答端，不在人工标注的区域端。这个设计的意义是：“哪些细节重要”不必完全由人事先定义，可以通过“丢掉这些细节后，模型理解是否发生变化”间接学习。

它也不是把一个硬选择器直接接上最终 loss、一次训成。三个阶段各管一个问题：

  • 第一阶段先让粗表示本身有用。 所有区域都用粗 token，只训 pooler，其余冻结，解决“少量 token 能不能承载有用内容”，还不学哪里该粗、哪里该细。
  • 第二阶段让选择器收到下游误差。 只训 router，用连续的粗细特征混合代替硬选择。这一阶段仍保留 100% 的 token 位置，并没有真正形成推理时的短序列；可微的混合让回答损失能影响路由概率，平衡项给出使用粗表示的压力。单纯要求“回答不要变”，最容易的做法是始终保留全部细节；单纯要求“token 少”，又会损害回答。第二阶段在两者之间训练选择。
  • 第三阶段让读取模型适应真正压缩后的输入。 切换成与推理一致的硬路由和混合粒度序列，训练 pooler 与 LLM，router 冻结。软混合时能读，不代表真正删减位置、混排粗细之后也能读。

最有价值的不是机械照搬三个阶段，而是它把三个学习问题分开了：压缩表示有没有表达能力，选择器能否得到有效反馈，读取模型能否理解最终的表示。 这个 proposal 同样会碰到这三个问题，只是选择器还必须遵守更严格的信息时间边界。

Cyrus 的判断是：VW 这类自监督的学习方式，可能也比较适合训练我们的 CUA model，让它逐步学会归纳和归类。以下各节都围绕这个判断展开。

4. predict 到底在决定什么

4.1 “按 patch 裁高价值区域”：哪里对，哪里要改

推断：

patch（或 VW 那样 4×4 patch 的块）很适合当“位置”的单位。processor 和分辨率固定以后，下一屏的网格是事先知道的；选区落到块上，token 账本也按块算，和 processor 一致。在已经到手的帧上（历史帧，或 O_{t+1} 到达之后的补看），按块挑也完全成立，而且可以按任务挑。建议默认用 VW 的块：4×4 个 patch，在 Qwen3-VL 上是 64×64 像素、2×2 个视觉 token，和 VW 增补实验 A 的切法一致；token 账本仍按 32×32 的视觉 token 算。块的大小在 P0 冻结，小目标吃亏时再试 32×32。

要改的地方在时间上。predict 发生时 O_{t+1} 的 patch 还不存在，“高价值”没法从下一屏的像素上算。能用的只有已经看过的帧（O_t 和历史）的 patch、任务和刚发的动作。所以 predict 实际是在预测：这个任务下一步缺什么信息，它会落在下一屏的哪些块上。

“价值”本身也要重新定义。我建议用 VW 的尺子：看了一个区域以后，模型的决策和看全屏时有多接近（保真度），以及为此花了多少 token。6.2 节的最小充分集固定保真度、找最少的 token；第 9 节的评测固定 token 预算、比保真度。两种口径用的是同一个保真度。按这个定义，文字多的区域、像素变了的区域、下一次点击的位置，都不能直接当高价值区域：只看图像的 router 能学到的，只是内容上的倾向；原报告也说变化框只能当召回辅助；项目数据里，抄动作位置命中证据 0/23。

4.2 三个因子：需求、位置、置信

推断（后面的数据和管线都基于这个分解）：

  • 需求：下一步决策缺什么信息。它来自任务、历史和刚发的动作。例如提交搜索之后缺“结果列表的标题和价格”，点“加入购物车”之后缺“是否成功的反馈”，输入文字之后缺“联想下拉里有没有目标项”。
  • 位置：这个信息会出现在下一屏哪里。来源有四种：历史里见过的同类页面（布局复用，proposal 的核心机制）；当前屏本身（动作不改布局时）；界面惯例（toast 在顶部或底部，模态框居中，下拉在触发控件下方，移动端键盘在底部）；动作的几何（滚动方向露出的条带，被点控件的邻域）。
  • 置信：对位置有多确定。第一版不单独输出一个置信数，而是体现在预测形态上：确定时给紧框；不太确定时给大框；遇到没见过的布局，就回退到粗看整屏，把定位交给 check 和补看。标签按附录 B 的三档生成。

Cyrus 说的“归纳和归类”，我理解落在前两个因子上。需求可以归类：结果列表、状态反馈、表单字段、导航目标、错误提示、确认对话框。位置规律可以归纳：同一模板同一位置，下拉在触发控件下方，新页面的主体内容在标题之下。第 6 节的自监督信号会在大量 transition 上反复告诉模型“这种需求、在这种布局下，信息在这里”。模型能从中归纳出跨应用、跨实例的规律，还是只记住每个页面的坐标，是这条路线要检验的核心假设；第 9 节专门在新页面族上测这一点。

每个样本该花多少 token 差别很大，这也支持让预测形态随置信变化。论文报告：Matryoshka Multimodal Models（ICLR 2025）给每个样本挑“答对所需的最少 token 档位”做 oracle，MMBench 上平均只要 8.90 个 token，准确率 74.35，比固定用 576 个 token 的 67.96 还高；DocVQA 这类密集文字任务平均要 64.09 个。论文没有训练会自己挑档位的选择器。

5. 显式还是隐式：三条实现路线

Cyrus 的问题“special token 的 hidden state 直接控制选择，还是引导模型输出观察请求再由环境执行”，对应下面的打分头路线和文本路线。第三条“先看后选”是放宽时间边界的版本。三条路线不用字母编号，免得和实验 A 到 E 混淆。

论文报告（本次核对）：在 GUI 和通用 VLM 里，都没有找到用“图像到达之前算出的 hidden state”去选择这张未来图像区域的同行评审工作。最接近的是：fVLM（只有代码，没有论文）由 LLM 处理完上一帧后的 hidden state 生成下一帧的查询；StreamAgent、FORESIGHT（均为 arXiv 预印本）用不训练的提示，让模型用文本规划未来帧里该关注的时间段、区域或类别。结构上最像打分头路线的是更早的 Recurrent Attention Model（NIPS 2014）：在一张静态图上，每次只根据之前几次注视形成的内部状态决定下一次看哪里（还没看过的区域对它同样未知），定位网络用 REINFORCE 训练，计算量可以和输入图大小无关。前瞻的结构在别的领域有先例，见 6.6 节。

文本路线：显式请求

<predict> 后输出一段短 JSON，环境按它返回观测。建议的格式：

{"needs": "result_list", "regions": [[40, 180, 620, 900]]}
{"needs": "page_body", "fallback": "coarse_full"}
{"needs": "none"}

needs 从一个固定词表里选，起点是 result_list（结果列表）、status_feedback（状态反馈）、form_field（表单字段）、nav_target（导航目标）、error_msg（错误提示）、dialog（确认对话框）、page_body（页面主体）和 unknown；none 表示下一步不需要新的细节（v2 下只看粗图，crop-only 下不取 crop）。词表以后看 needs 核对时对不上的样本（7.2 节）再调。regions 是至多 3 个 [0,1000] xyxy 矩形，渲染时对齐到块；它是一个 bundle，里面的区域都要看。不太确定时给一个大框（附录 B）；fallback 表示回退到粗看整屏。

  • 好处：每一步的决策都能读、能审计，便于人工复核和归因；现有 SFT 栈直接能用；时间边界天然成立，区域生成完，环境才插入 O_{t+1}。
  • 代价：坐标走文本 token，格式脆弱（项目数据：AGW 的受限链被 point 格式全部挡下）；每步多一段解码，增加时延。
  • 建议的三处修改： 1. loss 只算决策内容：needs 的取值、区域坐标、是否回退。JSON 的键和括号由约束解码给出，<predict> 标记由控制器插入，都不进 loss。依据是 E1：模板留在 loss 里时，NLL 的降幅大半来自答案的第一个格式 token，决策内容的信号被稀释。 2. 输出用约束解码（JSON schema 或语法约束），不让格式错误掩盖决策质量。 3. 保留 needs 字段写需求类型，只写 prefix 已能定义的信息类型，不写目标值。这是“归类”的显式形式，也让我们能直接看需求判断有没有随任务变（needs 的准确率），和第 9 节的条件敏感度互相印证。先写需求再给位置有一点旁证，但不强：项目里 32B 先写计划再报点，抄动作坐标从 13/14 降到 2/14，可最终的需新观察字段仍只有 3/24；自由文本的计划和一个类型化的 needs 字段也不是一回事。原报告 notes 记的 ScreenSeekeR（ScreenSpot-Pro 论文里的规划器）消融里，去掉“邻近元素推断”，ScreenSpot-Pro 上从 48.1 降到 46.4。needs 的标签从哪里来，见 7.2 节。

打分头路线：前瞻打分

在 <predict> 位置取 LLM 的 hidden state，用一个小的打分头给下一屏每个块输出“细看”的概率。key 有两组。一组是已经看过的帧（O_t、历史参照帧）的块特征，对应“上次 X 出现的地方”。另一组是下一屏网格的固定位置编码，对应“新露出的条带”“toast 区域”这类在已见内容里没有对应物的位置。原报告 notes 指出，GUI-Actor 式的头只指向可见图像的 patch，用在下一帧上只能表达“复制已见位置”，表达不了“结果会出现在折叠线以下”。第二组 key 就是为了补这一点。训练决策文档已经把“合法 prefix 到固定坐标 basis”列为 S4 区域头的改造方向，本文在此之外加了第一组 key，让头能直接指向已见帧里的对应位置（推断）。

论文报告（本次核对）：

  • GUI-Actor（NeurIPS 2025）在同一个 Qwen2-VL 底座、同一份数据上比较了注意力头和生成坐标：ScreenSpot-Pro 40.7 对 15.6（点）和 13.8（框），ScreenSpot 88.3 对 85.1。它的监督覆盖多个 patch：凡与 GT 框重叠的 patch 都算正例，loss 是 KL。
  • 同一篇里，冻结底座、只训头和 special token（7B 上约 1.03 亿参数）只有 22.9、73.5、74.9（ScreenSpot-Pro、ScreenSpot、ScreenSpot-v2），远低于连底座一起训的 40.7、88.3、89.5。
  • Visual Perception Tokens（ICCV 2025）：训练过的“格子选区 token”比文本框更好，DocVQA 0.369 对 0.219。
  • 可微选择怎么做影响很大。DiffPrune（arXiv 预印本）把 Soft Top-K 换成 Gumbel 直通估计，保留率从 95.5% 掉到 87.4%；AdaFocus V2（CVPR 2022）把 AdaFocus V1 的强化学习选块换成可微插值，训练快 2.2 到 2.4 倍，准确率高 1.0 到 1.5 个点。

训练可以照 VW 的三阶段来（推断）：

  1. 先用离线的块级软标签（第 6 节）监督打分头，给它一个合理的起点。打分头每块输出一个 0 到 1 的概率，用逐块二元交叉熵拟合软标签。它和 GUI-Actor 都用多块软目标，但 GUI-Actor 在所有 patch 上输出一个归一化分布、用 KL 训，正例是与 GT 框重叠的 patch；这里每块独立出概率，正好接上第 2 步的按块混合，目标来自保真度。
  2. 再照 VW Stage 2 做软混合，这一步只训打分头（和 VW Stage 2 只训 router 一样）。打分头只读 prefix，给出每块的概率 p_b；在 O_{t+1} 上，第 b 块按 p_b 混合清晰版和模糊版，读取器冻结，在 teacher 回答上算 KL，梯度经视觉塔传回打分头；再加一个预算项，作用同 VW 的平衡项。模糊版用 VW 增补 6.2 节的像素近似：每 2×2 像素并成 1 个，再放大回原尺寸。混合放在像素空间，是因为现成的 Qwen3-VL 没有 VW 那样的粗细两套 token，要等弹性编码器（7.5 节）才能在特征上混。和 VW 一样，这一步保留全部 token，不省算力。未来信息只出现在 loss 里，输入仍然只有 prefix，不破坏时间边界。
  3. 最后照 VW Stage 3：换成硬选择，按真实合同渲染，打分头冻结，训读取器。现成 Qwen3-VL 上，按分数从高到低取块，取到 token 预算为止，再合并成至多 3 个矩形（附录 B），和文本路线一样，避免 E2 里拼格的损失；只有原生弹性编码器能直接吃块掩码。
  • 好处：块级、可微，正好对应“按 patch 选”；选择不占解码 token，每一步都做也便宜；GUI-Actor 的对比说明，头在精细定位上可能明显好过文本坐标。
  • 代价：要改模型结构和推理服务（环境接收块掩码或合并后的矩形）；审计要看热力图；更容易学成只看图的显著性，6.4 节的对照数据对它更要紧。
  • 一个折中是需求显式、位置隐式：先用文本写出 needs，打分头在写完需求的位置上出分。需求可读、可审计，位置交给更精细的头（推断）。

要训哪部分（直觉）：只训一个 special token 的 embedding 多半不够。当时的想法是：只训 embedding 相当于 prompt tuning，它能改变模型“问什么”，但这里要的能力在基座里本来就弱（8B 自选区域 0/48），要改的是 LLM 怎么把任务、布局和动作合起来算。两条论文证据指向同一方向：GUI-Actor 冻结底座时差很多（见上）；论文报告，Lester 等（EMNLP 2021）发现，大多数模型规模下 prompt 长度要超过一个 token 才行，只有最大的 T5-XXL 用单个 token 也能有强结果，而且那是在 SuperGLUE 这类基座已有能力的任务上。验证办法很便宜：同一份 predict 数据，只训 embedding（加头）和训 LoRA（加头）各跑一版，比选区效用。

先看后选：放宽时间边界的对照

O_{t+1} 到达后，视觉塔先完整编码，一个以 LLM 当前状态（任务、历史）为条件的选择器决定哪些块细、哪些粗，LLM 的上下文里只进粗图加选中的细节。这就是“VW 加上任务条件”。建议直接用打分头路线的同一个头来做，只在 key 里加上 O_{t+1} 的块特征。这样它和打分头路线的差距只来自“有没有看到下一屏”，不混进结构上的差别。

  • 好处：选择看得到内容，比前两条路线容易得多；进入 LLM context 的 token 一样少，长程上下文的收益也一样。
  • 代价：不再前瞻。视觉塔要处理整屏，编码端的计算省不下来；选择用到了下一屏像素，和 1.2 节“做出初次观察选择时，模型还没有看到下一屏”不一致。

论文报告（本次核对）：GUI 上按任务挑 token 的工作都属于这一类，选择发生在截图编码之后。FocusUI（CVPR 2026）用指令引导的打分器，7B 在 ScreenSpot-Pro 上保留 30% token 时从 48.3 降到 45.1；STP-GUI（arXiv 预印本）用约 200 万参数、PPO 训练的窗口打分器，Qwen3-VL-2B 在 Online-Mind2Web 上保留 50% 时从 0.373 降到 0.350。

建议：先看后选只做对照，在 P1 里和打分头监督版一起训（7.2 节）。它和打分头路线的差距，量的是“必须在看到之前决定”的代价；看任务的选择器和不看任务的选择器之间的差距，量的是任务条件化的价值。这两个数决定 proposal 的两个核心主张站不站得住。

三条路线的关系与建议

在“粗看整屏、细看选区”的合同下（VW 增补 6.4 节的 v2），O_{t+1} 到达后粗图已经在上下文里，补看可以依据粗图的像素来定，不违反时间边界；只有初次 predict 必须前瞻。先看后选不一样，它要视觉塔先读完整的高清下一屏。crop-only 合同下，补看只能依据已经拿到的 crop 和 prefix（推断）。

建议：

  • 第一轮以文本路线为主。它不改模型结构，可审计，现有 SFT 栈能用。可预测性本身用实验 D 在标签上直接测，不靠哪条路线训出来的结果去推。
  • 标签按块级软标签存（第 6 节），P1 里用同一份数据训一个打分头的监督版（上面第 1 步）做对照，直接回答 Cyrus“要不要显式 predict”的问题，额外成本主要是打分头的工程。这等于把训练决策文档里后置的 S4 区域头提前成 P1 的对照。两道门用同一个指标，即第 9 节的同预算选区效用：监督版“不比文本路线差”（差值的 95% 置信区间下限高于 −0.05，即非劣效）就开软混合分支（第 2 步）；“超过文本路线”（区间下限大于 0）且只读合法 prefix，才进主线，这沿用 S4 的进入条件。
  • 先看后选只当对照；v2 合同下，补看可以按粗图像素来选。

6. 自监督信号从哪里来

6.1 离线全信息：每一种选区都能事后算出够不够

推断：这要两个前提。一是 O_{t+1} 在采集时完整存下（原报告要求存原始分辨率帧和 DOM/AX；现有小样本是否都有，要在 P0 清点）。二是“看哪里”不改变环境：动作 A_t 已经执行，下一屏是什么由 A_t 决定，和模型选看哪些区域无关。两个前提成立时，对每条 transition，任何候选选区 S 都能离线渲染成学生会看到的画面，再算出这个画面够不够用。原报告已经指出“任何反事实 crop 的证据效用都能离线重算”，这里补上它对训练方式的含义。

用强化学习的话说，单步上这是一个“全信息”问题：每个动作（选区）的回报都能算出来，不像在线交互那样只能看到自己选的那个。于是“该看哪里”可以变成监督学习：先算出好选区，再让选择器学，不需要靠探索去碰。VW 处在同样的位置（静态图上，粗细怎么分不改变图本身），我的理解是它用软混合拿梯度，因为块的组合太多，没法逐个搜。我们两条路都能走：文本路线用“先搜后学”，打分头路线用软混合。

论文报告（本次核对）：Learning by Cheating（CoRL 2019，下称 LBC）是这种“特权 teacher 教只看部分信息的学生”的经典做法：teacher 看鸟瞰地图，学生只看相机。它强调 teacher 可以在任意状态上被查询，不限于原轨迹走过的状态，所以学生能在自己走到的状态上拿到监督。

三件事会让这个性质打折扣：

  • 多步影响。这一步看了什么会留在历史里，影响以后的决策；某个区域现在不需要、两步以后需要，单步标签看不到。论文报告：Query-Independent Variable-Rate Visual Token Coding（arXiv 预印本）发现，同一张图上为一个问题算出的注意力排序，拿去给另一个问题用，输出 KL 在 Qwen3-VL-4B 上升高约 47% 到 51%，8B 上升高约 73% 到 123%（读自图中标注）。为某个需求选的区域，未必能服务以后的需求。第一版先忽略这一点，留给多步优化。
  • 标签依赖读取器。同一个选区，对 32B 够用，对 8B 可能不够（比如小字）；读取器训过以后也会变。所以给候选打分要用学生自己的读取器（VW 就是同一个模型自蒸馏），读取器更新后要重算。
  • O_{t+1} 只是一次采样。异步加载时，截图的时机会改变画面。原报告要求记录 settle 策略和是否超时，就是为了判断这一帧是不是稳定状态。建议：超时或没稳定下来的帧不当紧框正例，归到 4.3 节的异步类：过可达性门的降为大框，不过门的回退，S* 留作 P2 的补看目标。

6.2 保真度探针：怎么算“够不够”

建议（在 VW 增补 6.2 节的基础上扩展；各项阈值的起点见附录 B）：对一条 transition，

  1. teacher：冻结的基座模型，输入合法 prefix 加完整的 O_{t+1}，给出下一轮输出（测什么见 6.3 节）。O_{t+1} 用合同允许的最高分辨率，也就是细看用的分辨率；否则学生能读清的小字 teacher 读不清，KL 反而罚学生。teacher 始终是冻结的基座，和 VW 一样；变的是给候选打分的读取器，第一轮就是基座本身，P2 之后换成当前读取器（6.5 节）。
  2. 候选选区：结构化候选、块网格，以及当前模型只看 prefix 采样出的选区。结构化候选包括 DOM/AX 节点框、OCR 文本行、EFR 式的相邻帧差分框（灰度差分找变化区域，再由 VLM 标成相关或噪声）、WMA 式的前后帧元素匹配结果（用匈牙利算法匹配元素，得到新增、删除和更新），后两种原报告都介绍过。
  3. 打分：对每个候选 S，按合同渲染学生画面（crop-only 下只给 S，v2 下粗图加 S 细），算两项，定义同 VW 增补 6.2 节。分布保真是 teacher 回答上的逐 token KL，按 VW 在 top-512 上归一化；结果保真是贪心解码出的动作、坐标或字段是否与 teacher 一致。两项都过阈值才算“够用”，自然任务轨道的组合规则见 6.3 节。阈值建议用相对值，即信息恢复率 r(S) = [KL(∅) − KL(S)] / [KL(∅) − KL(全屏)]。∅ 是同一合同下不给任何细节的画面（crop-only 下就是没有 O_{t+1}，v2 下是只有粗图），KL(全屏) 是读取器看整屏时的 KL。第一轮读取器就是 teacher 本身，KL(全屏) 为 0，r 化简为 1 − KL(S)/KL(∅)；P2 之后读取器和 teacher 不同，分母要带上 KL(全屏)。
  4. 出标签： - 先判 none（附录 B）：满足时 S 记为空，标签是 {"needs": "none"}，不再搜索，也不过可达性门。 - 最小充分集 S：贪心联合搜索得到的近似最小集。从结构化候选开始，每次加入“r 的增益除以 token”最大的一项，直到够用，再逐个试着删掉多余的。它不保证是真正的最少。 - 可接受集合：在一个固定的候选池里，够用且 token 不超过 S 1.5 倍的全部 bundle，进 acceptable_bundles。候选池是：单个结构化候选、它们的两两组合、贪心搜索路径上的集合、模型采样的选区。 - 块级软标签：每块在可接受集合里出现的频率，按每个 bundle 的 token 成本反向加权，取值 0 到 1，就是打分头的监督目标。单块粗化的敏感度会低估冗余（6.5 节），不直接拿来当目标。 - 文本路线的区域目标：把 S 的块按连通域合成矩形，超过 3 个时保留 r 增益最大的 3 个，转成 [0,1000] xyxy。合成后重算一次 token 和够不够用；不够用就改用 S* 的外接框，还不够用就只出大框标签。
  5. 过可达性门：原报告规定，oracle 区域只有在“某个只看 prefix 的采样候选和它重叠”或“prefix 里已有该位置的布局证据”时，才当 predict 正例。“布局证据”用实验 D 的规则预测器来判（附录 B）。过不了的，predict 标签用回退，S* 留作 P2 的补看目标。区域形态按附录 B 的三档定。

成本上（直觉），所有候选共享同一个 prefix（历史、O_t、A_t），可以只算一次 prefix 的 KV cache，再对每个候选只算 O_{t+1} 部分和回答部分。当时的想法是：多图 prefix 占了请求的大头（视觉 token 中位占输入的 59%），复用它最划算。候选数量用结构化候选和分层二分压到每条十几到几十个；块级软标签从可接受集合里统计，不需要每块一次前向。即便这样，我估计探针的算力也是普通 SFT 造数的几十倍。这个数没有实测，验证办法是先在 100 条 transition 上测一次探针的 GPU 时间，再定规模。第一轮的起点是几千条核心 transition 做全量探针，其余用便宜的候选生成，再抽样跑探针验证。

6.3 teacher 的“回答”测什么

VW 的 teacher 回答一个给定的问题。CUA 里没有现成的问题，要先定“保真”是对什么而言。先区分两类样本：自然任务轨道按真实任务走，目标是下一步动作；辅助字段轨道在 predict 之前就在输入里声明要读哪个字段，目标是字段值（2026-10-10 的选择合同审计 THINK_CONTEXT_SELECTION_AUDIT_20261010.md 要求两者分开）。“回答”的候选有四种（推断）：

  • (a) teacher 自己生成的下一步动作（含简短推理）。自然任务轨道的默认选择。缺点是很多步的动作本来就不太依赖新内容，比如点了“加入购物车”以后，下一步往往是去结算，只看动作会低估“确认反馈”这类需求。
  • (a′) 记录轨迹里真实的下一步动作：在受限画面和全屏下分别算它的似然，看这个画面对该动作有多少支持。好处是不受 teacher 自己出错的影响（轨迹成功时尤其可靠），思路接近 Hindsight Experience Replay（NIPS 2017）用实际达成的结果事后重标目标。它不是 KL，用同样的相对形式：r′(S) = [log p(a|S) − log p(a|∅)] / [log p(a|全屏) − log p(a|∅)]。要注意的是，坐标 token 的似然主要取决于能不能看到下一步要点的元素，会把 S 拉向下一步动作的目标。这个元素本来也要看见才能操作，进 S 不算错，但它代替不了决策证据。所以 (a′) 拆开算：r′ 只用动作类型 token 的似然；坐标只看落在哪个元素上，把贪心解码出的坐标映射到 DOM/AX 元素，和记录动作的目标元素比，算作结果保真；确认类证据由 (c) 补。
  • (b) 预先声明的字段。用于辅助字段轨道。
  • (c) 状态核对问题：“上一步动作生效了吗？页面上出现了什么新状态？”用来补 (a) 的盲区。

建议：自然任务轨道用 (a′) 为主、(a) 为辅，再加 (c)；辅助字段轨道用 (b)。自然任务轨道上，“够用”要同时满足三条：(a′) 的 r′ 达到阈值，目标元素一致，(c) 的状态核对答案和全屏一致。这条轨道上，6.2、6.5 节和附录 B 里凡是用 r 比较候选的地方（贪心增益、矩形取舍、随机选区对照、none 的判定），都换成 r′。没有记录动作时（比如改写任务的合成对），用 (a) 代替 (a′)，再加一个随改写一起生成、答案能用 DOM/AX 核对的需求问题（6.4 节）。teacher 的推理如果写得很长，会把和任务无关的描述（比如顺手描述了侧栏）也算进 KL，把选区往外拉。所以 KL 要按 token 加权，动作和字段 token 权重高、自由描述权重低，或者让 teacher 用简短的固定格式回答（直觉：长推理里大部分 token 和关键证据无关，均匀加权会让标签偏向“描述全屏”；验证办法是在人工金标子集上比较均匀加权和按 token 加权，看哪种算出的 S* 和人工标的证据区域更一致）。有记录动作或 judge 结果时，只在 teacher 正确时用它的回答做标签。GHD 也只在 teacher 和示范动作一致时才蒸馏（GHD 是原报告介绍过的、把下一屏当特权信息的自蒸馏方法，原报告 notes 已核）。

6.4 让选择器真的用上任务：反事实需求对

推断：如果训练数据里每一屏只配一种需求，选择器只看图就能把 loss 降下来，任务输入可有可无。VW 提示了这一点：它的 router 完全不看问题（本次核对：论文算法 1 的输入里列了文本上下文，但 router 的计算步骤没有用到它），仍然保住了约 98.9% 的原生分数。不过同一个 benchmark 上直接降采样也有 91.04（VW 91.43），说明这类 benchmark 本身经得起压缩，留给任何选择器的空间都不大。两点放在一起看：常见数据上，只按图像分配很可能已经够把 loss 降下来；要教出任务条件化，就得专门造“只看图不够”的数据，评测也要挑经不起压缩的样本，比如小字和密集界面。一个能看任务的选择器，遇到普通数据，同样可以不用任务。

论文报告（本次核对）：任务条件化有多大用，取决于任务和数据。

  • 支持的一面：InstructBLIP（NeurIPS 2023）去掉 Q-Former 里的指令输入后，held-out 平均掉约 5 个点，空间推理和时间推理掉得最多（ScienceQA-IMG −7.0；Vicuna-7B 上 iVQA −15.4）。CDPruner（NeurIPS 2025）按指令选 token，64 个 token 时保留 97.0%，不看文本的 VisionZip 是 94.4%。
  • 有条件的一面：“Token Pruning in MLLMs: Are We Solving the Right Problem?”（Findings of ACL 2025）的结论是，只有当任务和语言信息强相关时，语言信息才有助于剪枝；VisionZip（CVPR 2025）则认为，按文本相关性挑出的 token 常常缺少信息。
  • GUI 上的一面：按任务剪枝的方法在 GUI 上表现很差。GUIPruner（arXiv 预印本）报告，按指令在 LLM 之前剪枝的 CDPruner 在 Mind2Web 上从 35.2 崩到 6.8；“Where and How to Prune”（arXiv 预印本）发现，历史截图上按文本剪枝不比随机好，当前截图则不该剪（FastV 剪掉 50% 时 AITW 从 0.7035 降到 0.6612）。Feather the Throttle（ICCV 2025）发现，按注意力剪枝受 RoPE 位置偏置影响，会系统性地剪掉图像上方的 token，定位任务的平均分只有 5.9，均匀采样反而有 28.0。
  • 没有找到在 GUI 上、同等训练条件下对照“看任务”和“不看任务”的选择实验。

推断：GUI 上这些失败，我的理解是主要来自破坏了空间结构，缺任务条件不是主因。token 剪枝的结论能不能搬到 crop 式观测上，要靠实验 C 看；稳妥的做法是选择器保住全局粗图和位置信息。

关于捷径和对照数据，论文报告（本次核对）：

  • VQA v2（CVPR 2017）为每个问题找一张相似、但答案不同的图组成互补对。在不平衡数据上训的模型，换到平衡验证集上普遍掉 6 到 7 分（MCB 从 60.36 降到 54.22，只看问题的模型从 48.21 降到 41.40）。
  • 反事实增强数据（ICLR 2020）让标注者对文本做最小改动、翻转标签，消除了“horror”“romantic”这类伪关联，域外表现提升（BERT 在 Amazon 上 85.1 对 80.0，Yelp 上 89.4 对 85.3）。
  • LBC 的“白盒”监督：特权 teacher 对同一个状态给出所有导航指令分支的动作，学生在所有分支上同时学。导航任务消融里，普通两段式 16%，只加 on-policy 64%，只加白盒 96%，两者都加 100%。

我们的情况和 VQA v2 正好反过来：那里是模型不看图，这里是模型可能不看任务。道理一样，数据里一路输入就能解释标签时，模型会只用这一路。

建议：

  • 需求要体现在输入里。成对样本之间不同的必须是输入：改写后的任务指令，或辅助字段轨道里另一个预声明字段。如果输入不变、只换输出里的 needs，教出来的是“自己挑一个需求再给位置”，学不到任务条件化。
  • 自然对：用版面聚类找出不同 session、不同任务访问同一模板的屏。例如同一个购物结果页，一个任务找最便宜的，一个找评分最高的。它们的差别里混着屏幕内容和历史的差别，适合用来估计“真实数据里需求不同、该看的区域也不同”有多常见。
  • 合成对：同一条 transition，保留真实的历史和动作，让 LLM 只看 prefix 改写任务指令（检查历史动作和新任务仍然说得通），或者换一个预声明字段，再用 6.2 节的探针在 O_{t+1} 上算各自的 S*。这就是 LBC 的白盒监督：teacher 能对同一状态的每种需求都给标签。改写任务的合成对没有记录动作，保真度用 (a) 加一个随改写一起生成的需求问题（比如“第一个结果的价格是多少”），问题的答案用 DOM/AX 核对，核对不了的对不用。合成对说明的是“需求可以有多不同”，不能拿来估计真实数据里的比例。
  • 两个 S 的 IoU 低于 0.3 才算有效对比（直觉*，起点），其余当普通样本。

训练之前，先在这些对上算 S 之间的 IoU 分布（7.1 节实验 E），自然对和合成对分开报。自然对的差别里混着屏幕内容的差别，所以自然对里有效对比的比例是任务条件化作用的上限。这个比例低于 10%，说明在真实数据分布上任务条件化收益有限，反事实数据只少量保留；高于 30%，还要用合成对确认差别确实来自任务，再按 7.2 节的配比投入；在两者之间，先按配比的下限投入，看 P1 的条件敏感度再调（几个数都是直觉*起点）。这是 Cyrus 对 VW 的批评能不能落到实处的直接检验。

6.5 探针本身的局限

论文报告（本次核对）：保真度探针本质上是扰动式的重要性估计，遮挡或粗化之后看输出变化。这类方法有两个已知问题。

  • 分布偏移和真实重要性混在一起。ROAR（NeurIPS 2019）发现，不重新训练时，在 ImageNet 上随机去掉 90% 的像素，准确率就掉到 0.5%；重新训练后，同样随机去掉 90% 还有 63.53%（干净图 76.68%）。没训练过的模型在被遮挡输入上的变化，有一部分只是“没见过这种输入”，不说明这块重要。ROAR 的办法是重训以后再测。
  • 单块遮挡会低估冗余信息：同一信息出现在两处时，单独遮掉任何一处都不影响输出。RISE（BMVC 2018）用随机掩码加权平均来估计重要性，ResNet50 上 deletion/insertion AUC 为 0.1076/0.7267，滑窗遮挡是 0.1421/0.6618（这两个指标本身也是扰动式的）。

另外，Feather the Throttle 的结果提醒，用模型注意力当标签有位置偏置。扰动式标签不直接读注意力分数，至少避开了这一层；但读取器本身的偏置仍会带进标签，下面的随机选区对照和人工金标就是用来查这个的（推断）。这是我倾向用探针、不用注意力图做标签的原因之一。

建议：

  1. 最小充分集用联合搜索，块级软标签从可接受集合里统计（6.2 节），都不直接拿单块敏感度卡阈值。
  2. 随机选区对照：每个候选配 4 个和它 token 数相同的随机选区，候选的 r 要比它们的平均高出 0.2 以上（直觉，起点），才出紧框标签。高不出来，说明这一屏信息冗余，或者读取器对受限画面普遍不敏感。这对应 VW 打乱路由的对照。
  3. 第一轮用基座当读取器算标签；P2 之后读取器见过受限画面，再重算一次，比较两次标签的一致率。这是 ROAR“重训后再测”在这里的对应做法。
  4. 实验 A（VW 增补第 7 节）原来检查的是逐块粗化得到的敏感块和已复核证据框的重合。P1、D、E 用的都是 S，所以本文让 A 再按 6.2 节算出 S，判定看 S* 和证据框的重合。现有证据框是 assistant 复核的，不是人工金标，所以 P0 里要先做一小批人工金标（⑧，起点 100 条，calibration 和 test 各一半）。通过标准和不通过时的退路见 7.1 节。

6.6 观测合同：前瞻选择的先例都带一个低清全局兜底

论文报告（本次核对）：

  • 360° 视频的视角自适应传输。 Flare（MobiCom 2018）按头部运动预测未来视角，只取视角内的高清块。中位预测准确率（看到的块全部落在预测集合里才算对）在提前 0.2、0.5、1、3 秒时分别是 90.5%、72.9%、58.2%、35.2%；作者建议始终下载一份最低分辨率的全景作兜底；LTE 上省带宽 26% 到 35%。双层方案（Sun 等，IEEE JETCAS 2019）用低码率全景层兜底，再用高质量层传预测视角；没有预测时只有约 17.01% 的接收比特落在视野里，预测准确时约 60.5%。
  • 机器人前瞻。 FoveaVLA（arXiv 预印本，2026-10）在策略下一次被调用之前，预测“下一次交互区域”的框；下一帧以 224×224 的低清全图加一块原始分辨率的 224×224 crop 输入，框无效时沿用上一个有效框或退回全图。成功率 70.8%（单相机）、77.1%（双相机），对照的 π0.5 加腕部相机是 52.1%。
  • 前瞻注视成像。 Policy-based Foveated Imaging（arXiv 预印本，2026-06）用低清全图流加卡尔曼滤波预测的框，在高分辨率读出之前选好后续若干帧的高清区域。像素预算只有 1/8 时，跟踪 IoU 0.283，全分辨率 0.281，均匀降采样只有 0.122。
  • 多分辨率 MLLM。 InternLM-XComposer2-4KHD（NeurIPS 2024）去掉全局视图后多数指标下降（MMBench 从 79.5 降到 75.1，InfoVQA 从 50.5 降到 47.9，DocVQA 从 79.4 降到 78.1）；Monkey（CVPR 2024）和 UReader（Findings of EMNLP 2023）的消融大多也支持保留全局图（UReader 的 ChartQA 是例外）。
  • 澄清一条旧警告。 原报告 notes 据 ZoomClick 表 9 建议不要在 crop 旁附缩略整图。本次核对：表 9 的模型是 UI-TARS-1.5-7B，“完整上下文”指的是上一轮缩放的输入图加点击点，和当前缩放图一起输入（从 54.1 降到 19.0），不是当前屏的缩略整图。原报告正文写的是“revisit 轮不回灌上一轮的整张图”，没有问题；notes 里的引申不能直接套到 v2 合同上。

推断：这些领域在“预测会出错”这一前提下，都收敛到同一种结构：低清全局兜底，加预测区域的高清细节。这和 VW 增补提出的 v2 合同一致。它对我们还有三个好处：预测偏了能在粗图上发现并补看；补看可以按粗图像素决定（第 5 节最后）；读取器始终有全局，和全屏 teacher 的信息差只剩分辨率，蒸馏门控更好做。代价是每次观测的 token 比 crop-only 多（VW 增补估计 1.6 到 2.2 倍）。建议：把 v2 当作实验 C 的主假设、crop-only 当对照，由实验 C 定。

7.1 P0：先定合同，再做诊断

VW 增补的实验 B（分辨率 × 表示）、C（观测合同对照）照旧；实验 A（像素空间敏感度探针）改为判 S*（6.5 节）。附录 A 有每个实验一句话的定义。新增两个只用标签、不训练的分析：

  • 实验 D：前瞻可解释比例。 用一个规则预测器估计 S 有多少能从 prefix 推出来。它只看 prefix 和刚发的动作，按动作类型查一张固定的映射表给出区域，规则有四种：当前屏的对应位置、同模板页面的变化区、动作几何、界面惯例的固定区域（定义见附录 B）。映射表在看 S 之前写定；给出的区域按同 token 预算扩或截（附录 B），否则框画得越大，越容易盖住 S。报规则预测器整体的覆盖率，每条规则的覆盖率也单独报；不在每条 transition 上事后挑覆盖最好的规则，那样会高估。同时报简单基线：抄动作位置、屏幕中心、上一步的选区、O_t 上的变化框。所有数按 4.3 节的转移类型分开报；转移类型由完整的 transition 判定（比如 URL 有没有变），只用来分层，不进规则的输入。规则预测器能覆盖的比例，是给定预算 B 时“可以前瞻”的下界估计（区域大小用了由 S 定的 B）：规则能做到的，模型至少有机会学到；规则解释不了的，模型未必学不会。它告诉我们第一轮该把数据集中在哪些转移类型，规则预测器本身也是可达性门的判据（6.2 节）。
  • 实验 E：任务条件化是否必要。 在反事实需求对上算 S* 之间的 IoU 分布，自然对和合成对分开报。判定看自然对里有效对比的比例，读法见 6.4 节，三档阈值见附录 B。

建议的顺序：第一步是清点现有数据，看哪些 session 存了原始分辨率的后继帧、settle 记录和 DOM/AX（第 8 节①）。探针要用原始分辨率的后继帧，判断是不是稳定帧要用 settle 记录，结构化候选和需求问题的核对要用 DOM/AX；缺的先补采集。然后 B、C 先跑，它们不依赖探针，用来定分辨率、块网格和观测合同；合同冻结以后再跑 A，因为探针渲染的学生画面取决于合同；D、E 要用 A 的探针，跟在 A 后面。C 里附带报告的“保真度标签和 K 次回放的一致率”，等 A 跑完再补。人工金标和 B、C 同时开始。五个实验分别决定五件事：观测合同（C）、细看用多高的分辨率（B）、探针能不能当标签（A）、数据集中在哪些转移类型（D）、任务条件化投入多少（E）。

实验 A 的通过标准（直觉，起点）：S 覆盖人工金标证据区域面积的 80% 以上，且 S 的面积有一半以上落在证据区域内。探针的阈值（τ、KL 加权等）先在金标的 calibration 一半上冻结，通过与否只看 test 一半。不通过时，P1 退回原报告的标签：DOM/AX 节点框、EFR 差分框、WMA 匹配候选给出 oracle 区域；只看 prefix 采样的 bundle 按原报告的四项验收（对某个 oracle bundle 的覆盖率、只看 crop 时 K 次回放的效用、预算、精度），合格的取 token 最少者当正例（原报告取面积最小，本文按第 11 节的建议用 token 计）。探针只记录、不进训练。附录 B 里用 S 定义的项（同 token 预算 B、可达性门、区域形态三档、needs 核对）都用这个 oracle 正例代替 S；P2、P3 和第 9 节里的“够用”改用原报告的 K 次回放效用。D 改用 oracle 区域代替 S* 来算；E 只算自然对和换预声明字段的合成对，改写任务的合成对要靠探针出标签（6.4 节），先不算。

VW 增补 6.5 节原来的排期是第 1 轮只记录探针、第 2 轮起才进训练。本文把探针当主要标签来源，所以建议实验 A 通过就在 P1 用；想保守的话，可以保留原排期，P1 先用 oracle 标签（第 11 节）。

7.2 P1：训选择器

建议：

  • 行类型：只有 predict 行。输入是合法 prefix；第一轮里，prefix 中的 O_t 和其他历史帧都按现在的整屏低分辨率渲染。<predict> 标记由控制器插入，不进 loss；监督目标是 needs（含 none）和区域形态（紧框、大框、回退）。
  • 区域标签按附录 B 的三档生成。紧框档用 S，或每个 epoch 从可接受集合里轮换抽一个完整 bundle（训练决策文档的做法；可接受集合只收 token 不超过 S 1.5 倍的 bundle，所以不会把明显更贵的选区当正例；文本路线上，抽到的 bundle 也要合成至多 3 个矩形，见附录 B）；大框档用全部可接受 bundle 的外接框；回退档用回退目标。反事实对的两边都进训练。
  • needs 标签：让 LLM 只看 prefix 和动作写出需求类型（和合成反事实对用同一个生成器），再拿 S 区域在 DOM/AX 里的元素类型核对，例如 S 落在列表项上就对应“结果列表”。对不上的样本只训区域，needs 这一项不进 loss。判为 none 的样本，needs 直接记 none。
  • 历史帧怎么渲染：如果历史帧也按模型自己当时的选区存，prefix 本身就依赖策略，选择器也要在自己产生的 prefix 上训（7.3 节 DAgger 的道理同样适用）。第一轮建议历史帧仍按现在的整屏低分辨率渲染，把这个依赖推迟到历史压缩那一步。
  • 对照：三个对照和主线用同一份数据。打分头监督版（第 5 节第 1 步）；先看后选（同一个头，key 里加 O_{t+1} 的块特征）；不看任务的选择器（同样的结构和训练，只是输入里去掉任务指令和预声明字段，保留图像、历史动作和刚发的动作）。不看任务的选择器在一对样本上看到的输入完全一样，条件敏感度按定义是 0。
  • 配比（直觉，起点）：按转移类型均衡，常见的原地更新类设上限；回退目标约占 predict 行的 15% 到 25%；反事实对约占 20% 到 30%；全观察回归数据按 token 占总量的 20% 到 30%，这部分和回归门的评测集分开，按 session 和近重复簇切分（原报告的划分规则）。当时的想法是：回退样本太少，模型学不会承认不确定，太多又会一律回退（VisionThink 不加惩罚就会总是要高分辨率，原报告 notes 已核）；反事实对要多到让“只看图”的捷径在 loss 上明显吃亏；回归数据是为了不让训练冲掉原有的 grounding 和动作能力。调的时候看三个量：选区效用；回退率，不能塌到总是回退或从不回退，大致应接近数据里不可预测样本的比例；全观察回归分数。
  • 规模（直觉）：先做 1k、3k、10k 条 transition 三档学习曲线。当时的想法是：相邻工作的 SFT 规模从几千（Chain-of-Focus 约 4.5k，Mini-o3 约 6k 条冷启动轨迹）到几万（LookAgain 约 7 万条轨迹）不等（原报告 notes），而本项目连“prefix 能不能预测证据位置”都还没确认，先看曲线斜率比直接堆量更有信息。原报告建议的 1 万到 3 万条真实分支，可以作为曲线走好之后的目标。
  • 训哪部分（直觉）：LLM 全部线性层上 LoRA，rank 64 左右，视觉塔和 merger 冻结；打分头路线再加打分头。当时的想法是：要学的是新的条件化决策，旧 adapter 那样只学会格式不够；旧工程 smoke 的 rank 8、只调最后四层 q/v，容量太小（训练决策文档也写明它只是工程验证）。rank 64 是原报告 notes 记的 GuirlVG 默认值。算力允许时，另做一版全量微调 LLM 作对照。
  • 出口指标：见第 9 节。核心是在过可达性门的 transition 上、同 token 预算（定义见附录 B）下，P1 选择器的选区效用高于抄动作、屏幕中心、上一步选区和不看任务的选择器，条件敏感度大于零。样本小，一律报 95% bootstrap 置信区间，按 session 聚类；“高于”“大于”都指区间下限大于 0（附录 B）。

7.3 P2：在选择器自己的选区上训读取器

推断：VW 的 Stage 3 给了两条相关证据（论文报告，本次对照 PDF 核过）：不做 Stage 3，27B 的 ScreenSpotV2 只有 66.59，做完 91.43；粗块数不变、只把路由位置打乱，又掉到 59.28。读取器适应的是它训练时见过的那种选区分布。这两条直接说明的是“在压缩后的输入上训”有用，以及读取器对选区分布敏感；“在选择器自己的选区上训，好过在 oracle 选区上训”是由此推出来的，另外有下面 DAgger 和 LBC 的证据。放到我们这里，读取器要在 P1 选择器自己选出来的画面上训，包括选偏、选漏的情况。

论文报告（本次核对），同方向的证据：

  • DAgger（AISTATS 2011）证明，只在专家状态分布上训练的策略，一旦犯错就会进入没见过的状态，误差上界随步数平方增长；在学习者自己访问到的状态上让专家打标签，降到线性。
  • LBC 的消融里，只加 on-policy 监督，导航成功率从 16% 升到 64%。
  • ATP-LLaVA（CVPR 2025）冻结 LLM、只训剪枝模块时，四个 benchmark 都低于和 LLM 一起训（例如 MMB 63.1 对 66.0）。HiconAgent（CVPR 2026）只在推理时丢历史 token，AndroidControl 成功率 47.34；用它的方法训练后，同样的算力下是 52.40。
  • EPIC（NeurIPS 2025）用共享权重、压缩更少的 teacher 蒸馏，去掉蒸馏 loss 掉 1.3 到 1.5 个点，去掉“逐步加大压缩率”的课程掉 2.2 个点。

具体做法（建议）：

  1. 选区用交叉拟合生成：把训练集按 session 分成两半，用一半训出的选择器给另一半选，每条采样几个，不只取贪心，再渲染成学生画面。选择器在自己训过的样本上会选得比测试时好，读取器见到的分布就偏干净了。
  2. 按 6.2 节的“够用”标准判断每个画面： - 够用：读取器蒸馏 teacher 的回答（下一步动作或字段），check 标为证据充分。 - 不够，但补看能补齐：check 标为不足，补看目标取补齐代价最小的那个可接受 bundle 缺的块（只在 labels_only 里算）。v2 合同下，证据只在粗图上模糊可见时，check 记 seen_coarse（VW 增补 6.4 节），补看就是把这些块升级成细。 - 证据不在这一屏（要滚动或换页才能看到），或者总预算用完也补不齐（预算按训练决策文档的 whole_plan_utility，把 predict、check、补看合起来算）：自然任务轨道回退整屏，或者让下一步动作去找（滚动、翻页）；辅助字段轨道答 unknown，对应 present_but_hidden。 - 画面能证明字段不存在：visibly_absent。要两条同时成立：完整状态（DOM/AX 或全屏 teacher）确认字段不存在，并且授权画面里能看到“不存在”的证据，比如空的结果区（训练决策文档的规则）。
  3. 门控：画面里没有证据时，不拿 teacher 的回答当目标，否则就是在教“没看到也照答”。直接的依据是 PI-Distill（teacher 掌握的信息离学生能推出的越远，效果越差）和 E2：8B 看不到证据还给具体值，正是这一步要纠正的行为。GHD 的门控（只在学生失败、且 teacher 和示范动作一致时蒸馏）保证的是目标正确，和这里“目标要能从学生的画面推出来”是两回事，只算相关做法。
  4. 课程：参照 EPIC，先用宽松的预算，再逐步收紧。
  5. 回放：P1 的 predict 行按一定比例混进来，免得共享的 LoRA 在 P2 里把选择能力冲掉。

回答要不要 on-policy，证据不一致（论文报告，本次核对）：VW 在 4B 的 Stage 3 上试过学生自己 rollout，论文称和 off-policy 的平均分相近、各赢 4 项（off-policy 平均 72.59；on-policy 的约 72.21 是按图中数值算的）。GKD（ICLR 2024）在摘要、翻译、数学推理上发现，让学生在自己生成的序列上由 teacher 逐 token 打分，明显好于在固定序列上蒸馏。Thinking Machines 2025 年的博文（非同行评审）转引 Qwen3 技术报告的数字：AIME'24 上强化学习用 17,920 GPU 时得到 67.6%，on-policy 蒸馏用 1,800 GPU 时得到 74.4%，用约十分之一的算力超过了强化学习。我的理解（推断）：回答越长、越依赖自己前面写的推理，on-policy 越重要；VW 的回答短，所以没差别。我们的 check 和动作输出都短，第一版用“选区 on-policy、回答 off-policy”就够；以后 check 里如果有长推理，再试 on-policy 蒸馏。

选择器和读取器共用一个 LoRA 还是各用一个（直觉）：predict 和 check 本来就是两次调用，中间环境要返回画面，所以各用一个 adapter 在服务上可行，也最接近 VW“一个冻结、另一个训”的分离。代价是两次调用之间不能共享 prefix 的 KV cache：LoRA 改了 k/v 投影时，同一段 prefix 在两个 adapter 下的 KV 不同，每次 check 都要重新 prefill 多图历史。第一版建议共用一个 LoRA、P2 里回放 predict 行。这和 VW Stage 3 冻结 router 不一样：共用 LoRA 时选择器没有冻结，只靠回放保住选择能力，所以 P2 的出口要复测一遍 P1 的选区指标。如果观察到 P2 明显冲掉了选择能力，再试双 adapter。

7.4 P3：迭代

建议：用当前模型对每条 transition 只看 prefix 采样 K 个选区（起点 K=8，直觉），按 6.2 节的探针离线评估，留下“够用且最省”的那个做新的 predict 标签；再用新的选择器重新生成 P2 的读取器数据。训练部位和 P1、P2 相同，接着训同一个 LoRA。这就是训练决策文档里的 rejection-SFT。Cyrus 说的“逐步”可以对应到这里：每一轮的标签由上一轮模型自己采样、由全细节 teacher 判，不需要人工。

几条约束：

  • 同一 prompt 上，更省的兄弟样本也成功时，不收更贵的那个（原报告 notes 的组相对规则）。P1 的可接受集合只收 token 不超过 S* 1.5 倍的 bundle，是同一条规则的宽松版。
  • 只有同 prompt、同预算的候选之间出现稳定、可审计的效用差，才考虑 DPO（训练决策文档 S3 的条件）。
  • 强化学习的位置。论文报告（本次核对）：SFT Memorizes, RL Generalizes（ICML 2025）在规则和视觉分布变化下发现，结果奖励的强化学习能泛化，SFT 会退化（V-IRL 规则变化下 SFT 从 80.8% 跌到 1.3%，强化学习 +11.0）；同一篇也报告，直接从基座做强化学习在所有学习率下都失败，要先用 SFT 把输出格式稳定下来。推断：单步上标签可以离线算，第一版不需要强化学习去找好选区，先 SFT 后强化学习的顺序也合理。如果按转移类型对齐以后，P1 选择器在新页面族上仍明显不如训练页面族，说明它更多是在记坐标；这时可以考虑把探针分数当奖励做单步强化学习。落差一定要按转移类型分开比，否则新页面族里不可预测的类型多一些，也会表现成落差。多步预算分配和补看策略，也留给强化学习。

7.5 两个独立分支

  • 打分头的软混合：数据和标签与 P1 共用，按第 5 节的第 2、3 步训。进入条件是 P1 里打分头监督版在同预算选区效用上不比文本路线差（第 5 节的定义）。
  • VW 原生弹性编码器：VW 增补 6.5 节的弹性基座分支照旧，与本管线并行、不混在一起。它解决“同一帧怎么编码更省”，和“看哪里”正交，也是第 2 节说的“真正省 token”的前提之一。过了 VW 增补 6.5 节的门（同 token 数下不低于直接降采样）以后，可以当 P1 到 P3 的基座。

条件敏感度是检验 Cyrus 对 VW 批评的直接指标：只看图的选择器，在同一屏的两种需求下给出一样的选区，这个数就是 0。评测集要包含经不起压缩的样本（小字、密集界面），否则任何选择器都显不出差别（6.4 节）。样本小，所有数都带置信区间。

长程收益对应 1.1 节“进一步希望获得的收益”，目前只有间接证据（论文报告，本次核对）：

  • 历史截图的边际收益很快变平。OpenCUA（NeurIPS 2025）里 1、3、5 张历史截图的 OSWorld 成功率约为 6.5、9.6、9.9（柱状图与数值的对应是按图注推断的），作者认为 3 张到 5 张收益很小，还多出约 3K token，默认用 3 张。UI-Genie 的奖励模型（NeurIPS 2025）在难样本上 3 张历史图比 5 张好（71.5 对 68.7）。
  • 历史 token 经得起大幅裁剪，当前帧不行。“Where and How to Prune”里，历史截图随机只留 10% token 时 AITW 0.6842，全留是 0.7035。
  • 文本记忆很要紧。SecAgent（arXiv 预印本）只留 1 张历史截图加一段滚动的文本摘要；去掉摘要，任务准确率从 72.8 掉到 56.4。
  • 少看可能反而更好，但看模型。“Screenshots or Tools?”（arXiv 预印本）用“操作成功就丢掉截图”的规则，Qwen3-VL-8B 在 OSWorld-MCP 上从 33.0% 升到 37.8%，只用了 53% 的输入 token。The Complexity Trap（NeurIPS 2025 workshop）在 SWE-bench Verified 上只保留最近 10 个观测，Qwen3-Coder 480B 解题率 54.8%、成本减半（原始 53.4%），但 Gemini 2.5 Flash 反而从 40.4% 降到 36.4%。
  • Context Rot（Chroma 2025 技术报告，非同行评审）在 18 个 LLM 上发现，输入越长，表现越不稳定；只给约 300 token 的相关内容，明显好于给约 11.3 万 token 的完整上下文。

推断：这些证据说明“少放视觉 token、多靠文本记忆”在不少设置下不伤甚至有益，但都没有直接测“按任务选进入上下文的区域”。长程收益只能在多步评测里测，用在线环境，或者够长的离线回放。

12. 还没回答的问题

  • prefix 到底能预测多少。实验 D 之前，不知道真实数据里可前瞻的转移占多大比例。如果多数步骤是没见过的页型，收益会很有限。
  • 探针标签和人工证据是否一致。实验 A 和第一批人工金标之前，不知道探针算出的 S* 和人工金标的证据区域重合多少。
  • 同 token 下看得更清，能不能换成任务收益。近期不省 token（第 2 节），这一点要由实验 B 和端到端评测证明。
  • 有多少样本经不起压缩。常见 benchmark 上直接降采样也能保住大部分分数（6.4 节），真实 CUA 数据里需要细看的样本占多少还不知道。
  • 多步影响。单步标签不管“现在不需要、以后需要”的区域，为某个需求选的区域也不一定能服务以后的需求。
  • 长程收益。没有直接测“按任务选区”的证据，只能在多步评测里测。
  • 没有现成先例。本次和原报告的检索都没有找到在 GUI 上、下一屏到达之前预测其区域的工作。最接近的先例在机器人和流媒体领域（6.6 节），多是预印本或系统论文，迁移到 GUI 要自己验证。

可达性门 当前模型只看 prefix 采样 K 个选区，其中有一个和 S 的 IoU 达到阈值；或者 S 被实验 D 的规则预测器覆盖 K = 8，IoU 0.3 看 P1 选择器在过门样本上的选区效用是否高于不过门的（按统计一行判）。这是校准用的诊断，和第 9 节只在过门样本上算的评测分开
有效反事实对 两个 S* 的 IoU 低于阈值 0.3 人工另标几十对同一屏的合成对，看 IoU 判定和人工判断“该看的地方不同”是否一致
实验 E 的判定 自然对里有效对比的比例，读作任务条件化作用的上限 低于 10%：反事实数据少量保留；10% 到 30%：按配比下限（predict 行的 20%）投入；高于 30%：先用合成对确认差别来自任务，再按 7.2 节的配比投入 中间一档看 P1 的条件敏感度再调
实验 A 的通过 在金标 test 一半上，逐条算 S 覆盖证据区域面积的比例和 S 落在证据区域内的面积比例，各自取均值；判为 none 或没有证据区域的不计 80%、50% 探针阈值在金标的 calibration 一半上冻结
人工金标的切分 calibration 和 test 各一半，按 session 和近重复簇切（原报告第 0 轮的切分规则）；阈值只在 calibration 一半上调 100 条，各 50 条 扩到 300 条时用同样的切法
条件敏感度的筛选 只用 U_A(S_A) − U_A(S_B) 不小于阈值的方向。这一项太小，说明两种需求在 oracle 上差别不大，计入只给分子添噪声 0.2 报去掉了多少，换 0.1 和 0.3 看结论变不变
统计 95% bootstrap 置信区间，按 session 聚类。和 0 或另一个方法比较时，“高于”“大于”“超过”指区间下限大于 0（比较两个方法时用差值的区间）；“不比……差”（非劣效）指差值的区间下限高于非劣效界。实验 A、E 的阈值按点估计判，同时报区间；区间跨过阈值时，先扩大样本再判。比较对象和门槛在看结果之前定好 非劣效界 −0.05 无
