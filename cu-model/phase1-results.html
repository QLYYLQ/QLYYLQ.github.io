先说判断

基础视觉定位和布局精判已经足以支持下一轮造数；当前零训练的网格预测＋独立 crop＋一次补看流程，还没有表现成可靠、节省观察的执行策略。 32B改用原生焦点坐标后，在同24例、相同8-cell预算上从网格的2例命中提高到9例，但仍没有超过复制当前操作位置的10例。这不是对你的训练路线作 no-go 判断：当前帧也携带 session 信息，额外旧历史的增益不是唯一标准；短历史、动作框代理标签和观察表达方式都限制了这轮结论。

最有价值的直接产物是：一套严格隔离未来帧的可运行原型、303 条经 32B 精判接纳的 SFT 对话银标样例、两种基座的实际输出，以及能逐例检查预测区域和失败原因的图集。

后续 Phase 1b 修正： 独立审查发现原 SFT 对话没有显式监督边界，直接 all-assistant loss 会连故意选错区域的上下文一起训练。原文件保留，已另导出 completion-only 版本；实际 token mask 仍待训练器验证。语义可用性另行分层，见 Phase 1b 复核 与 机械审计。此修正不改变下文冻结的推理指标。

造数中做了几个实质性修正：

  1. OpenHands 的截图是同条动作的 post-action observation。预测输入取执行前截图＋当次动作，标签取结果截图上的下一点击；没有错拿刚执行动作的位置当未来标签。
  2. BrowserGym 的裸 click("bid") 对无编号截图不可解释。动作现在使用执行前的控件框、AX文字/role和真实输入参数，模型侧不再看到不透明元素ID。
  3. GUI-Odyssey 采用分卷ZIP定点读取并核验CRC，没有合并或解压整个86GB包。GUI-Xplore探索数据只作布局候选，未把随机探索点击冒充任务目标。
  4. Predict构造器对所有未来字段保持不变；未来截图、目标DOM、下一动作或框只供标签/离线judge。合法历史中原样出现过同一张截图属于重访控制，不当成未来泄漏。
  5. SFT的visible/missing分支都固定8 cells、面积12.5%，使用确定性匹配filler，teacher选择与实际裁剪一致，避免靠crop数量猜标签。正例超过8 cells的样本整组跳过并记录。

这些仍是训练格式的银标原型。 Layout接受不等于专家动作正确；“目标框可见/缺失”也不等于任务信息充分/不足，尤其原样重访时历史可能已经包含信息。它们适合检查协议和做小规模bootstrap，不能直接宣称是最终check能力的真值。尚未进行SFT或RL。

测量 8B 32B
完整截图＋明确控件query，点落目标框 73/97＝75.3% 79/97＝81.4%
下一屏不可见，带较早历史，前8格命中目标框中心 19/111＝17.1% 16/111＝14.4%

上述有效链路最终act落在记录的目标框 2/111 1/111

后四类都是离线回放代理指标，不是在线CU/BU任务成功率。完整目标屏的next-click条件只带原任务和最近三帧历史，可能缺少更早确定的客户、商品等任务状态；记录中的下一点击也未必是唯一正确动作。明确控件query的高定位分数不能转述成未来预测能力，而两者的差距也不能直接归因为规划能力差。

额外历史没有带来净命中提升：8B全111例是新增6例、丢失8例；32B新增6例、丢失9例。限定到同一73个较早reference可见样本，8B为13对13，32B为11对12。这只测额外旧历史的边际价值，不能否定当前帧布局复用。

另外，8B warm有48/111次把整行0–7放在前八，32B也常输出完整行。32B仍有8个warm输出违反0–63/去重协议。此处混合了输出表达问题和选区质量，不能据此排名一般模型能力。图集和 独立审计 保留了这些原始输出与严格/条件有效两套分母。

Layout judge 的价值与边界

与原silver标签的一致率是8B 195/240、32B 186/240。不能因此说8B更准确：web“不同URL模板”负例和mobile几何正例本来就有噪声。

在真实移动端reference-target候选中，8B仅接纳7/31，32B接纳12/31。独立、未看Qwen输出的assistant视觉审查确认了键盘输入页→结果页、普通表单→日期modal等误配；相似度超过0.9也不保证同布局。另一方面，8B把一个有意义的新酒店详情实例判成different，32B保留了它。因此最终保留模型分歧，后续judge应分开判断 same_template、spatial_reusable 和 changed_regions。

该assistant审查是有意抽取的有限案例，不是随机人标gold。16个明确布局案例上两模型分别一致16/16、15/16，只能作为具体纠错证据，不能外推总体准确率。见 视觉审查及图例。

观察预算和表达方式

主流程先看8/64 cells，最多再补8个新cell。零训练模型多次要求继续观察；到这轮25%累计面积上限时，很多样本还没有形成可执行动作。

本HF实现没有跨请求复用KV。每个样本实际调用的平均账本如下：

平均账本 8B 32B
predict＋check＋可能的revisit调用数 2.95 2.82
合计输入token 12,006 11,420
合计视觉token（含每次重编码的前缀） 6,680 6,361
各调用实测耗时之和 13.23秒 30.63秒
对照：一次完整目标屏next-click调用 2.23秒 3.86秒

即使扣除重复前缀，平均新增目标视觉token也约688／635，而完整目标图约481。独立crop的最小分辨率、坐标文本和补看开销都很实在，不能用“只看12.5%面积”代替token或加速结论。账本见 functional_chain.md；这些不是带KV复用或原位稀疏编码的性能上限。

还做了同24个样例的受控观察表达对照：完全相同的选中像素，分别作为独立crop，或放回原位置、其余区域变灰。8B初次check的记录框一致从0/24到2/24，32B仍为0/24；canvas视觉token反而平均增加约107。这个小对照说明表达方式值得检查，但没有提供稳定修复或节省token的证据。见 canvas报告及并列样例。

还用了同24个冻结样例做原生焦点诊断：模型只报一个0–1000整数点，控制器选距离它最近的8个网格中心，仍占12.5%面积。并列规则使用整数平方距离和cell id打破等距，避免浮点tie误差。原生模型只输出点，不需要口述网格编号。

同24例的中心命中 8B 32B
网格＋较早历史 4/24 2/24
原生焦点＋较早历史 4/24 9/24
原生焦点＋仅当前屏/动作 5/24 9/24

最后一行只有17/24例具有明确操作点，其余按全24分母计未命中。这说明不能把32B的提升都说成历史推理或自省：原生表达值得下一轮优先验证，但廉价的操作位置基线同样强。两个原生条件也没有更早历史的净增益。这24例来自两模型都生成了初次check输入的交集，再按平台和sample ID哈希选择；属于可执行预测子集，不代表全部111例。该诊断同时改变了输出表达和控制器映射，不替换主评估，也不用于识别内部机制；没有沿用均匀随机选cell的k/64当作这种点诱导mask的随机概率。见 原生焦点报告。

建议推进顺序

  1. 先造更对题的session。 优先真实search A→search B及同模板新实例；保留当前帧就是参照的合法情况，并保留完整任务状态。不要单纯增加宽松几何候选数量。
  2. 把信息证据标签补起来。 围绕标题、价格、结果关联等完整语义字段构造可见/缺失条件，区分“字段不存在”和“被裁剪遮住”；不要把任意下一点击框等同充分信息。
  3. 优先原生坐标/ROI或固定anchor头，再用小规模SFT教协议与观察行为。 不把口述网格编号当作基座空间能力的上限。使用现有原型检查loss/时序/格式，再扩可靠标签；同时保留完整任务的回归测量。3B下沉和任务RL保持在后续阶段。
  4. 实现位置与预算更忠实的观察接口。 合并相邻选区、保留全局位置并测prefix复用；调研中的FocusUI/AQuaUI等可以提供工程参照。这里要优化的是感知训练方式，而非把项目改造成未来帧生成。

更具体的下一轮数据配方和一手资料见 研究审阅第9节。
